# 中継の動かし方

手元の macOS または Ubuntu で中継を動かす手順と、動作確認の項目をまとめています。前提条件とインストール方法は [README.md](../README.md) を、仕様は [docs/relay.md](relay.md) を参照してください。

コマンドは、インストールした `agent-chat-relay`（別名 `ac-relay`）で書いています。リポジトリを clone して開発する場合は、`agent-chat-relay` を `scripts/relay.sh` に読み替えてください（データの置き場と秘密情報の扱いが違います。[README.md](../README.md#開発)）。

## LINE 公式アカウントとチャネルの準備（初回のみ）

Messaging API のチャネルは、LINE Developers コンソールから直接は作成できません。LINE 公式アカウントを作成し、LINE Official Account Manager（以下 OAM）で Messaging API を有効にすると、チャネルが作成されます。画面の名称は変わることがあるので、見つからない場合は近い名前の項目を探してください。

1. **公式アカウントを作成する**：<https://entry.line.biz/start/jp/> から、LINE ビジネス ID（個人の LINE アカウントでも可）でログインして作成します。アカウント名はグループのメンバーに表示される名前で、あとから変更できます。無料のコミュニケーションプランで始まり、認証済みアカウントの申請は不要です。
2. **Messaging API を有効にする**（OAM の Web 版でのみ操作できます）：<https://manager.line.biz/> で［設定］→［Messaging API］→［Messaging API を利用する］を選びます。プロバイダーは新規に作成してください。**プロバイダーはあとから変更できない**ので、業務で使っている既存のプロバイダーは選ばないでください。プライバシーポリシーと利用規約の URL は空欄で構いません。
3. **応答設定**（OAM の［設定］→［応答設定］）：チャットはオンにし、あいさつメッセージと応答メッセージはオフにします。チャットをオンにするのは、中継が受け取った発言に既読を付けるためです（ADR 0012）。手動の返事や自動応答が Bot の返信に混ざらないよう、OAM のチャット画面からは返事をしないでください。Webhook は、URL を登録するまでオンにできません。
4. **グループへの参加を許可する**（OAM の［設定］→［アカウント設定］→［トークへの参加］）：既定では許可されていません。1 つのグループに参加できる公式アカウントは 1 つだけです。
5. **必要な値を控える**（<https://developers.line.biz/console/> で、作成したプロバイダーのチャネルを開きます）
   - ［チャネル基本設定］の**チャネルシークレット**と、［Messaging API 設定］の**チャネルアクセストークン（長期）**（［発行］を押して発行）を、`agent-chat-relay secrets line` で保存します。チャットには貼り付けないでください。OAM の［設定］→［Messaging API］にはシークレットが平文で表示されるので、その画面のスクリーンショットも共有しないでください。漏れた場合は再発行して保存し直します。トークンを再発行すると、以前のトークンは使えなくなります。
   - ［Messaging API 設定］の QR コードは、Bot を友だちに追加するときに使います。

## Chatwork の Bot アカウントの準備（初回のみ）

1. **Bot 用の Chatwork アカウントを作成する**（無料プランで可）：表示名が、ルームのメンバーに見える Bot の名前になります。自分のアカウントは使わないでください。Bot の発言が自分の名前で表示され、自分宛てのメンションがすべて Bot に渡ってしまいます。
2. **API トークンを発行する**：Bot のアカウントでログインし、右上のメニュー →［サービス連携］→［API トークン］から発行します。組織の契約によっては、組織管理者への申請が必要です。トークンは `agent-chat-relay secrets chatwork` で保存します。チャットには貼り付けないでください。漏れた場合は再発行して保存し直します。
3. **コンタクトになる**：使う人と Bot をコンタクトにします。DM と実行承認の依頼は、コンタクト間のダイレクトチャットでやり取りします。無料プランでは、組織外のコンタクトは 1 ユーザーあたり 20 人までです。
4. Webhook とトンネルは不要です（ADR 0010）。

## Discord の Bot の準備（初回のみ）

1. **アプリを作成する**：<https://discord.com/developers/applications> で［New Application］を選びます。名前が、サーバーのメンバーに見える Bot の名前になります。
2. **Bot のトークンを取得する**：［Bot］→［Reset Token］で表示されたトークンを、`agent-chat-relay secrets discord` で保存します。チャットには貼り付けないでください。漏れた場合は作り直して保存し直します。
3. **Message Content Intent をオンにする**：同じ［Bot］の画面の［Privileged Gateway Intents］で、［Message Content Intent］をオンにします。オフのままだと、メンションのない発言の本文が空で届きます。
4. **サーバーに招待する**：［OAuth2］→［URL Generator］で、Scopes に `bot` を選びます。Bot Permissions には次を選びます。
   - View Channels
   - Send Messages
   - Send Messages in Threads
   - Create Public Threads（エージェントが、発言からスレッドを作るときに使います）
   - Read Message History
   - Attach Files
   - Add Reactions

   生成された URL を開き、使うサーバーを選びます。
5. Webhook とトンネルは不要です（ADR 0011）。非公開スレッドで使う場合は、そのスレッドに Bot を招待してください。

## 準備

- Claude Code（`claude`）をインストールし、ログインしておきます。中継は、PATH 上の `claude` を `claude-agent-acp` 経由で起動します。
- 秘密情報を保存します。LINE は `agent-chat-relay secrets line`、Chatwork は `agent-chat-relay secrets chatwork`、Discord は `agent-chat-relay secrets discord` で入力します。どれか 1 つだけでも動きます。環境変数で渡すこともできます（[README.md](../README.md#秘密情報の管理)）。
- 作業ディレクトリを独立した git リポジトリにできない場合（git がインストールされていない場合、作業ディレクトリの `.git` が壊れている場合、`GIT_DIR` などの git の環境変数でリポジトリの場所を変えている場合など）、中継は起動しません。エラーの文に、直し方（`.git` を確かめるか退避する、環境変数を外す、など）を表示します（[docs/relay.md](relay.md#構成)）。

中継が使うファイルは次のとおりです。置き場は `~/.agent-chat-relay/` で、`RELAY_HOME` で変えられます（ADR 0019）。

| 場所 | 内容 |
|---|---|
| `~/.agent-chat-relay/.env` | `RELAY_LINE_CHANNEL_SECRET`・`RELAY_LINE_CHANNEL_TOKEN`・`RELAY_CHATWORK_API_TOKEN`・`RELAY_DISCORD_BOT_TOKEN`（平文。権限は 0600） |
| `~/.agent-chat-relay/access.json` | ルームの登録、許可リスト、ペアリング待ちのコード |
| `~/.agent-chat-relay/workspace/` | セッションの作業ディレクトリ。受け取った添付ファイルは `.relay/inbox/` に保存し、7 日で削除します |
| `~/.agent-chat-relay/media/` | LINE に返信した画像（推測できない名前で公開し、7 日で削除します） |
| `~/.agent-chat-relay/harness.log` | ハーネスの標準エラー出力（画面には表示しません。異常終了したときだけ、最後の 20 行を表示します）。10MB を超えそうになると `harness.log.1` に移して新しいファイルに切り替えます |

## 起動

LINE を使う場合は、ターミナルを 2 つ使います。

1. `agent-chat-relay serve` を実行します（ハーネスは Claude Code）。OpenCode は実行承認が働かないため（#6）、`RELAY_ALLOW_UNSAFE_HARNESS=1` を付けない限り起動しません。試す場合も、信頼できる人だけがいるルームに限ってください。
   - 起動のたびに新しいセッションになります。前の会話を続ける場合は、前回の起動ログの「セッションを開始しました」（または「再開しました」）に表示された `sessionId` を指定します：`agent-chat-relay serve --session-id <id>`。再開できない場合は、理由を表示して起動を中止します（新しいセッションは作りません）。再開できるのは、中継の作業ディレクトリで作ったセッションだけです（[docs/relay.md](relay.md#セッションの再開)）。
2. `agent-chat-relay line-tunnel` を実行します。表示された `https://….trycloudflare.com` の末尾に `/line/webhook` を付けた URL を、LINE Developers コンソールの［Messaging API 設定］で Webhook URL に登録し、［検証］を押します。

   | ［検証］の結果 | 主な原因 |
   |---|---|
   | 401 | チャネルシークレットが間違っている。`secrets` で入力し直す |
   | 404 | URL の末尾に `/line/webhook` がない |
   | 502・530 など | 中継が起動していない、またはトンネルの URL が古い |

3. ［Webhook の利用］をオンにします。オフのままだと、検証が通っても発言は届きません。［Webhook の再送］はオフ（既定）のままにしてください。再送された依頼の扱いはまだ決まっていません（[docs/relay.md](relay.md#line)）。

Quick Tunnel の URL は、トンネルを起動し直すたびに変わります。そのたびに Webhook URL を登録し直してください。URL が古いままだと、発言は届かずに失われます。中継だけを再起動する場合、URL は変わりません。

停止するときは、両方のターミナルで Ctrl+C を押し、［Webhook の利用］をオフにします。

Chatwork と Discord だけを使う場合は、`agent-chat-relay serve` だけで動きます（トンネルは不要です）。

## 中継を分けて動かす

登録したすべてのルームの発言は 1 つのセッションに入るので、互いを信頼しない集団どうしで 1 つの中継を共有しないでください（[docs/relay.md](relay.md#構成)）。集団ごとに Bot を用意し、次の環境変数を変えて、中継を別に起動します。`serve` だけでなく、`secrets`・`pair`・`access`・`line-tunnel` も、同じ値を付けて実行してください。

| 環境変数 | 既定値 | 分ける理由 |
|---|---|---|
| `RELAY_HOME` | `~/.agent-chat-relay` | ルームの登録、許可リスト、秘密情報、作業ディレクトリ、ログを分ける |
| `RELAY_ENV_FILE` | `<RELAY_HOME>/.env` | 秘密情報のファイルだけを別の場所にする（通常は `RELAY_HOME` を分ければ足りる） |
| `RELAY_HTTP_PORT` | `18080` | Webhook と画像の配信のポートが重ならないようにする |
| `RELAY_MCP_PORT` | `18090` | チャット用ツールの MCP サーバーのポートが重ならないようにする |
| `RELAY_WORKSPACE`（`--workspace <dir>`） | `<RELAY_HOME>/workspace` | 指定しなければ、`RELAY_HOME` を分けると分かれる。指定する場合は、中継ごとに、互いに重ならないディレクトリにする（一方が他方を中に含まない）。もう一方の中継の `RELAY_HOME` も中に含めない。作業ディレクトリの中（受け取った添付の置き場 `.relay/inbox/` を含む）は承認なしで読めてルームへ返せるので、重なると、もう一方の集団のファイルや秘密情報を引き出せる。中継が起動時に確かめるのは、自分の `RELAY_HOME`、中継のパッケージ、秘密情報の置き場を含まないことだけ |

例：

```sh
export RELAY_HOME=~/.agent-chat-relay-b RELAY_HTTP_PORT=18081 RELAY_MCP_PORT=18091
agent-chat-relay secrets discord
agent-chat-relay serve
```

ほかに、次の環境変数で動きを変えられます。

| 環境変数 | 内容 |
|---|---|
| `RELAY_HARNESS` | `serve` でハーネスを省略したときのハーネス（既定は `claude`） |
| `RELAY_OPENCODE_MODEL` | OpenCode で使うモデル（省略すると OpenCode の設定に従う） |
| `RELAY_CHATWORK_POLL_SEC` | Chatwork の API をポーリングする間隔（秒。既定は 5、最小は 2） |
| `RELAY_PUBLIC_URL` | LINE に返す画像を公開する URL を固定する（省略すると、届いた Webhook のホスト名から決める） |
| `RELAY_APPROVAL_NOTICE_MIN` | 承認依頼に答えが出ないとき、ルームに「承認待ち」を知らせるまでの時間（分。既定は 10、1〜29。ADR 0024） |
| `RELAY_SLOW_NOTICE_MIN` | 返事もターンの終わりもないとき、ルームに「時間がかかっている」と知らせるまでの時間（分。既定は 20、1〜1440。ADR 0024） |

### 普段の環境で動かす

端末で使っているエージェントの作業フォルダ、設定、記憶を、そのままルームで使うための環境変数です（ADR 0017）。どれも、管理者が自分の責任で指定します。指定すると、その環境が承認なしで許していること（allow ルール、hooks、作業ディレクトリの中身を読むこと）が、登録したルームの誰の発言からでも使えるようになります。秘密情報を置いたディレクトリは、作業ディレクトリにしないでください。

`serve` のフラグでも指定できます。フラグは環境変数より優先します（ADR 0019）。例：`agent-chat-relay serve --workspace .`（起動したディレクトリを作業ディレクトリにする）。`scripts/relay.sh` はリポジトリ直下に移ってから動くので、相対パスはリポジトリ直下を起点にします。中継は `~` を展開しません。引用符で囲んだときや、秘密情報のファイルに書いたときは、`~` という名前のディレクトリとして扱われ、ディレクトリがないため起動しません。

| 環境変数（`serve` のフラグ） | 内容 |
|---|---|
| `RELAY_WORKSPACE`（`--workspace <dir>`） | 作業ディレクトリ。既定は `<RELAY_HOME>/workspace`。指定したディレクトリは作らず、`git init` もしない。`RELAY_HOME` や秘密情報の置き場を含むディレクトリは指定できない |
| `RELAY_HARNESS_SETTINGS`（`--harness-settings default`） | `default` で、ユーザー設定と CLAUDE.md・AGENTS.md を、その環境の既定どおりに読み込ませる（Claude Code） |
| `RELAY_HARNESS_MEMORY`（`--harness-memory`） | `1` で、自動メモリを有効にする（Claude Code）。ルームの発言をもとにメモリが書かれる |

記憶を持ったエージェントをそのままつなぐには、端末で使っているフォルダを `RELAY_WORKSPACE` に指定し、ほかの 2 つも合わせて指定します。指定したときに起きること（「常に許可」が端末のセッションにも効くことなど）は、[docs/relay.md](relay.md) と ADR 0017 にあります。

## ルームと承認者の登録（ペアリング）

1. Bot に 1 対 1 でメッセージを送ります。コードが返ってくるので、端末で `agent-chat-relay pair <コード>` を実行します。これで自分が許可リストに追加され、実行承認の依頼を受け取れるようになります。
2. Bot をグループに招待します（招待済みの場合は、Bot にメンションしてメッセージを送ります）。コードが返ってくるので、同じように `pair` を実行します。
3. 登録した内容は `agent-chat-relay access` で確認できます（ID は伏せて表示します）。

## 動作確認の項目（LINE）

| 操作 | 期待する結果 |
|---|---|
| 登録していないグループで Bot にメンションする | コードが返る（Reply なので通数を消費しない） |
| 登録したグループで Bot にメンションして質問する | すぐに既読が付き、返信が届く |
| Bot に 1 対 1 で質問する | すぐに既読が付いてローディングが出て、返信が届く |
| メンションせずに発言する | 返信はない |
| グループ A で「グループ B に〜と投稿して」と頼む | B に投稿され（Push）、A に報告が届く |
| 画像を送ってから、メンションして「さっきの画像を説明して」と頼む | 画像の内容を踏まえた回答が届く |
| Bot に 1 対 1 で、動画・音声を送る | すぐに既読が付き、受け取ったことへの返信が届く（中身を読めるかは、ハーネスの環境による） |
| Bot に 1 対 1 で、位置情報・スタンプを送る | すぐに既読が付き、それぞれを踏まえた返信が届く |
| メンションして「さっきの画像をそのまま返して」と頼む | 画像が届く。開くと元のサイズで表示される |
| メンションして、作業ディレクトリにファイルを作るよう頼む | 承認者の DM に承認依頼が届く。［許可］を押すと実行され、返信が届く |
| 承認依頼に［拒否］で答える | 実行されない |

Push は、グループではメンバーの人数分、承認依頼では承認者 1 人につき 1 通を消費します。今月の消費数は `agent-chat-relay line-quota` で確認できます。

## 動作確認の項目（Chatwork）

| 操作 | 期待する結果 |
|---|---|
| Bot を新しいグループチャットに追加する | 数秒でコードが投稿される |
| 登録したルームで、Bot に To を付けて質問する | 返信が届く（数秒遅れる） |
| To を付けずに発言する | 返信はない。あとで「さっきの発言は？」と聞くと、内容を読める |
| 中継を停止している間に To を付けて依頼し、そのあと起動する | 実行されない |
| ファイルを送ってから「さっきのファイルを要約して」と頼む | ファイルの内容を踏まえた回答が届く |
| 「〜を CSV にして送って」と頼む | 作業ディレクトリにファイルを作るための承認依頼が DM に届き、`yes <ID>` で許可するとファイルが届く |

## 動作確認の項目（Discord）

| 操作 | 期待する結果 |
|---|---|
| Bot に DM を送る | コードが返り、`pair` すると許可リストに追加される |
| チャンネルで Bot に `@` を付けて話しかける | コードが返る。`pair` すると、そのチャンネルが登録される |
| 登録したチャンネルで、Bot に `@` を付けて質問する | 発言に 👀 が付き、入力中の表示が出て、返信が届く |
| Bot の発言に返信する／`@everyone` で発言する | 返信には反応して返事が届く。`@everyone` には反応しない |
| 登録したチャンネルでスレッドを作り、Bot に `@` を付けて話しかける | 登録しなくても、スレッドに返信が届く |
| 登録したチャンネルで、Bot に `@` を付けて「スレッドを作って、そこで返事して」と頼む | その発言からスレッドができ、スレッドの中に返信が届く |
| 未登録のチャンネルのスレッドで話しかける | スレッドにコードが返り、`pair` すると親チャンネルが登録される |
| 中継を停止している間に発言し、起動してから「さっきの発言は？」と聞く | Discord の履歴を読んで答える |
| 画像を送ってから「さっきの画像を説明して」と頼む | 画像の内容を踏まえた回答が届く |
| 「〜を CSV にして送って」と頼む | 作業ディレクトリにファイルを作るための承認依頼が、ボタン付きで DM に届く。［許可］を押すとファイルが届く |
| 2,000 字を超える回答になる質問をする | 分割して届く |

## モックでの確認

e2e のスクリプトは、チャットサービスごとに `test/e2e/<サービス>.sh` に置いています（モックは `mock-<サービス>.ts`）。Discord は e2e を作らず、偽の Client（`test/fixtures/discord-fake.ts`）を使った単体テストと、実際の Discord で確認します（ADR 0011）。

| スクリプト | 内容 |
|---|---|
| `test/e2e/line.sh claude` | 中核。LINE の API をモックにして、ペアリング、返信、承認を確認します。承認は、許可・常に許可・拒否のそれぞれで答えます。常に許可は、Claude Code が作業ディレクトリの `.claude/settings.local.json` に足した範囲で確かめます。`--full` を付けると、別のルームへの投稿と、画像の説明と返送も確認します |
| `test/e2e/resume.sh claude` | 中核。LINE の API をモックにして、セッションの再開を確認します。合言葉を覚えさせてから停止し、`--session-id` で再開して、合言葉、返信、承認を確認します。存在しない ID では起動しないことも確認します |
| `test/e2e/chatwork.sh claude` | Chatwork の API をモックにして、ペアリング、返信、停止中に届いた依頼を渡さないこと、承認とファイルの返送、ルームへの追加を確認します。`--full` を付けると、画像の説明と、停止中に届いた依頼を記録から読むことも確認します |

各スクリプトは、手順ごとに成否を判定し（`ok:` か `NG:`）、1 つでも失敗すれば 0 以外で終わります。`--full` で加わる手順は、モデルの能力に頼るので、失敗しても中継の退行とは限りません（出力にもそう示します）。どの e2e を走らせるかは、`bun run mutation` が、`main` との差分から表示します（`scripts/e2e-targets.ts`。ADR 0023）。リリースの前には、中核を走らせます（`docs/releasing.md`）。

いずれも実際のハーネスを動かすので、契約の利用枠を少し消費します。ログと作業ディレクトリは、サービス名を付けて `.local/e2e/` に残ります（例：`relay-line-claude/`）。終わったら、Claude Code の会話ログ（`~/.claude/projects/` のうち `local-e2e` を含むもの）を削除してください。

開発中に Webhook を 1 件ずつ送りたい場合は、`scripts/relay.sh line-webhook text <ルーム> <ユーザー> <本文> [--mention]` などを使います（`scripts/line-webhook.ts`）。
