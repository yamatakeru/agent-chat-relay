> ADR 0019 で、3 つの環境変数に、同じ意味の `serve` のフラグ（`--workspace`、`--harness-settings`、`--harness-memory`）を足しました。フラグは環境変数より優先します。また、作業ディレクトリに含めてはいけない場所の「リポジトリ直下」は、「中継のパッケージ（開発時はリポジトリ）」になりました。

> `claudeMdExcludes` で除くものに、CLAUDE.local.md と `.claude/rules/` を足しました（#45）。CLAUDE.md・AGENTS.md だけを除くと、上位のディレクトリのこの 2 つが読まれることを、Claude Code 2.1.327 で確かめました。判断は変わりません。

> 秘密情報のファイルがシンボリックリンクなら、その実体のあるディレクトリも、作業ディレクトリに含めてはいけない場所にしました（#52）。`RELAY_ENV_FILE` のディレクトリだけを比べると、実体が作業ディレクトリの中にあっても起動していました。判断は変わりません。

> pi と OpenCode の初回対応での設定継承、自動メモリ、再開の範囲、OpenCode の生成設定の配置は、[ADR 0026](0027-harness-approval-and-settings.md) で決めました。Claude Code の扱いは変えません。

# 管理者は、作業ディレクトリとハーネスの設定の読み込みを、自分の責任で環境に合わせられる

中継は、ハーネスを、中継専用の作業ディレクトリ（`<RELAY_HOME>/workspace`）で、ユーザー設定・CLAUDE.md・自動メモリを読み込ませずに起動してきました。ルームのエージェントに、端末で使っているエージェントの設定や記憶を持ち込ませないためです。

これに対して、記憶や指示を持って動いているエージェントを中継につなぎたい（#36）、普段の作業フォルダを作業ディレクトリにして、そこにあるファイルをそのまま返したい（#37）、という要望が出ました。どちらも、実行承認と設定の読み込みに関わる安全境界（AGENTS.md）を緩めるものなので、2026-11-17 に、まとめて決めました。

## 分かったこと

**設定の読み込み**（Agent SDK の型定義 `sdk.d.ts`、公式文書の settings、実機）

- 中継が `_meta` の `settings` で渡す値は、`--settings` と同じ層（flag settings）に入り、ユーザーが制御できる設定の中で最も優先されます。1 つの値を持つ設定（`permissions.defaultMode`、`autoMemoryEnabled` など）は、中継の指定が勝ちます。
- 一方、`permissions.allow` などの規則と hooks は、ユーザー・project・local の設定と足し合わされます。中継の指定で打ち消すことはできません。hooks には、承認の依頼に答えるもの（`PermissionRequest`、`PreToolUse`）もあります。このリポジトリを開発している端末のユーザー設定にも、承認の依頼を別のアプリへ送る `PermissionRequest` の hook がありました。
- 権限モードは、中継が起動後に確かめて切り替えます（`src/harness/harness.ts`）。実機でも、`claude-agent-acp` はユーザー設定を読むかどうかによらず `auto` で始まり、中継が `default` へ切り替えました。
- CLAUDE.md は、作業ディレクトリから上のディレクトリへたどって読まれます。作業ディレクトリを git リポジトリにしても、たどるのは止まりません（実機で、既定の作業ディレクトリの 1 つ上の CLAUDE.md が読まれた）。今の構成で上位の CLAUDE.md を読まないのは、`claudeMdExcludes` で除いているからです。

**自動メモリ**

- 既定の置き場は `~/.claude/projects/<作業ディレクトリから決まる名前>/memory/` です。名前を作業ディレクトリから決めるのか、git リポジトリから決めるのかは、SDK の型定義と公式文書で書き方が違い、確かめていません。どちらでも、同じフォルダで使えば、端末のセッションと記憶を共有します。
- 実機では、メモリの目印を読ませることはできませんでした（`autoMemoryEnabled` を true にしても）。この環境で自動メモリが働かない理由は、確かめていません。

**作業ディレクトリ**

- default モードでは、作業ディレクトリの中のファイルは承認なしで読めます。ADR 0009 は、これを前提に、作業ディレクトリの中のファイルを承認なしで返せるようにしました。
- 作業ディレクトリには、受け取った添付（`.relay/inbox/`）、「常に許可」の記録（Claude Code では `.claude/settings.local.json`。ADR 0015）、OpenCode の設定（`opencode.json`）が書かれます。

## 決めたこと

- 次の 3 つの環境変数を足す。どれも、指定しなければ今までどおり。それぞれ単独でも使える。
  - `RELAY_WORKSPACE=<パス>`：作業ディレクトリを、管理者が指定したディレクトリにする。
  - `RELAY_HARNESS_SETTINGS=default`：ユーザー設定・CLAUDE.md・AGENTS.md を、その環境の既定どおりに読ませる（`settingSources` と `claudeMdExcludes` を渡さない）。
  - `RELAY_HARNESS_MEMORY=1`：自動メモリを有効にする（`autoMemoryEnabled` を true にする。ユーザー設定で切っていても有効にする）。
- 名前はハーネスを問わない形にする（ADR 0006）。今のところ、`RELAY_HARNESS_SETTINGS` と `RELAY_HARNESS_MEMORY` が効くのは Claude Code だけ。OpenCode は今もユーザーの設定を読んでおり、指定しても変わらないので、そのことをログに出す。
- `RELAY_HARNESS_SETTINGS` と `RELAY_HARNESS_MEMORY` に、決めた値以外が指定されていたら起動しない。空の値は指定なしとして扱う。安全境界に関わる指定の書き間違い（`true` など）を、黙って無視しないため。
- どれも、管理者が自分の責任で有効にするものとする。有効にしても、中継は次の 2 つを外さない。
  - 権限モードを default にする（`settings` での指定と、起動後に確かめて切り替えること）。ADR 0016 のとおり、実行承認を安全策の要のままにする。
  - チャット用ツール（`mcp__chat`）だけを、承認なしで使えるようにする（ADR 0008）。
- `RELAY_WORKSPACE` は、次のように扱う。
  - ディレクトリがなければ起動しない（作らない）。書き間違いで、意図しない空のディレクトリで動き出さないため。利用者が指定する作業ディレクトリを作らずにエラーにするのは、`git -C`、systemd の `WorkingDirectory=` などと同じ。
  - `.git` がなくても `git init` しない。管理者のディレクトリの性質を変えず、端末のセッションと同じ場所として扱うため。上位のディレクトリの設定から切り離すことは保証しない。
  - 中継のデータ（`RELAY_HOME`）か、秘密情報の置き場（リポジトリ直下と、`RELAY_ENV_FILE` のディレクトリ）を含むなら起動しない。作業ディレクトリの中は承認なしで読めてルームへ返せるので、含むと、ハーネスに秘密情報を渡さないという境界（`withoutRelaySecrets()`）が割れるため。
  - 受け取った添付は、今までどおり作業ディレクトリの `.relay/inbox/` に置く。エージェントが承認なしで読めて、転送できる場所である必要があるため。git の無視対象にするかは、管理者に任せる。
  - OpenCode では、作業ディレクトリに、中継の書く内容と違う `opencode.json`、または `opencode.jsonc` があれば起動しない。管理者の設定を上書きしないため。
  - 同じディレクトリで端末から作ったセッションも、`--session-id` で再開できる。再開の制限（作業ディレクトリで作ったセッションだけ）の理由は、場所が変わると設定と返せるファイルの範囲が変わることで、場所が同じなら当たらないため。権限モードは、今までどおり再開時に default へ切り替える。
- ADR 0009 は accepted のまま残し、冒頭に、この ADR で前提が変わりうることを書く。

## Considered Options

- **1 つの起動オプションにまとめる（普段の環境で動かす）。** 分かりやすい。ただし、普段のフォルダは使いたいがユーザー設定は読ませたくない、といった組み合わせを選べない。
- **中継の側で、部分的に絞る。** たとえば、`.env` などの読み取りを deny ルールで止める。ただし、ユーザー設定の allow ルールや hooks だけを除く方法は `settingSources` にはなく、絞れる範囲が限られる。名前で守る方法は、漏れがあっても気づきにくい。
- **守りも含めて、すべて環境に任せる。** 権限モードと `mcp__chat` の指定も外し、その環境の claude の既定どおりに動かす。ADR 0016 と食い違い、ユーザー設定で `auto` や `bypassPermissions` にしていると、ルームの発言からの実行が人を通らなくなる。
- **自動メモリを、設定の読み込みと一緒に切り替える。** 変数は減る。ただし、ルームの発言がメモリに書かれる危険を、設定の読み込みとは別に、明示して選ばせたい。
- **指定した作業ディレクトリでも `git init` する。** 上位の設定から切り離せる（ただし、CLAUDE.md は上へたどられる）。管理者のフォルダの性質が変わり、端末のセッションと同じ場所として扱えなくなる。
- **指定したディレクトリがなければ作る。** 今の既定の作業ディレクトリと同じ扱い。書き間違いで、空のディレクトリで動き出す。

## Consequences

- 有効にすると、その環境が承認なしで許していることが、登録したルームの誰の発言からでも使えるようになります。
  - `RELAY_HARNESS_SETTINGS=default`：ユーザー設定の allow ルールと hooks が効きます。承認の依頼に答える hooks があれば、中継の実行承認を通らずに実行されることがあります。ユーザーと上位のディレクトリの CLAUDE.md が、エージェントへの指示として読まれます（既定の作業ディレクトリと組み合わせても、中継のリポジトリの上位の CLAUDE.md が読まれます）。
  - `RELAY_WORKSPACE`：そのディレクトリの project の設定（`.claude/settings.json` など）が効きます。中のファイル（`.env` などを含む）は、ルームの誰かの依頼で、承認なしで読まれ、ルームへ送られえます。秘密情報を置いたディレクトリを指定しないでください。
  - `RELAY_HARNESS_MEMORY=1`：ルームの発言（承認者でない人の発言を含む）をもとに、メモリが書かれます。`RELAY_WORKSPACE` で普段のフォルダを指定していると、そのメモリは、管理者の端末のセッションにも読まれます。ルームから持ち込まれた指示が、残り続けることがあります。
- 普段のフォルダを指定すると、「常に許可」の記録はそのフォルダの `.claude/settings.local.json` に書かれ、管理者の端末のセッションにも効きます。許可リストに管理者以外の人がいれば、その人が選んだ許可も効きます。
- 端末のセッションを中継から再開すると、端末での会話の内容がエージェントの文脈に入り、ルームの誰でも、エージェントを通して引き出せます。逆に、中継のセッションは、端末の `claude --resume` の一覧に出ます。
- 指定した作業ディレクトリには、`.relay/inbox/` ができます。
- 端末で使っているエージェントの記憶や指示を、そのままルームで使えます。#36 の目的（記憶の索引を持ったエージェント）には、`RELAY_WORKSPACE` で普段のフォルダを指定し、`RELAY_HARNESS_SETTINGS` と `RELAY_HARNESS_MEMORY` を合わせて指定します。ただし、自動メモリが読まれることは、実機では確かめられていません。
