# 変更した行のミューテーションテストを、fallow で、レビューの補助として行う

PR #78 で、修正に足した条件（`if (!done && (await steer(text))) continue` の `!done`）を外しても、どのテストも落ちませんでした。エージェントは、その場面を「テストの偽物では起こせない」として、PR の「確認できなかったこと」に書いていました。実際には、偽物を差し替えれば起こせました。

`AGENTS.md` の「手元でできる検証は報告前に済ませる」の行は、手元で確かめられるかを、書く本人が判定します。そのため、確かめられないと判断すれば、規則を満たせてしまいます。変えた条件がテストで守られているかを、本人の判定ではなく、道具に出させることにしました。2026-11-19 に決めました。ADR 0020 で見送った StrykerJS の代わりに、fallow を使います。

## 分かったこと

**StrykerJS 10.1.1**（変更した行に絞り、テストを `bun test` で動かす形で試した）

- Bun のランナーがなく、Node が必要でした。TypeScript 7 には JS の API がないので、tsconfig の前処理を外すなど、回避が 3 つ必要でした。
- 既定の変異に「`&&` の片方の条件を消す」がなく、#78 の穴を捕まえませんでした。
- CLI のテストは、環境変数を絞った子プロセスで `src/main.ts` を起動します。変異を選ぶ環境変数が子に渡らないので、`main.ts` の変異は、テストが確かめていなくても、確かめたうえで生き残ったように見えました（31 個）。

**fallow 3.44.0**（`fallow mutation`）

- `bun test` のランナーを持ち、Node なしで動きます。変更した行だけを対象にし、変異ごとに、その行を通るテストだけを動かします。
- 既定の変異に、「`&&` の片方の比較か `!x` を `true` にする」があります。#78 の当初（384f1a7d）で、`!done` を外した変異を生き残りとして出しました（変異 11 個、33 秒）。
- テストが届かない変異は、生き残りと分けて `no_coverage` とし、どこまで届いたか（`test_reach`）を付けます。`direct` は、テストがそのモジュールを読み込んでいるのに、その行を通っていないものです。承認の答えを ACP の選択肢に対応させる行（#79）は、ここに出ました。`none-file` は、どのテストもそのファイルを読み込んでいないもので、子プロセスでだけ動く `main.ts` は、ここに入ります。
  - （追記 2026-11-20）この記述は、決めた時点では成り立っていませんでした。fallow は、入口から読まれないファイルの変異を dead code として外し（`pruned`）、Score と Coverage の行に入れません（出力の末尾に `Pruned: 6 dead-code` と件数だけを出します）。入口は `package.json` の `main` の `bin/agent-chat-relay` だけと見ていましたが、これはシェルなので、`src/main.ts`、そこからだけ読まれる `src/prompt.ts`、`scripts/line-webhook.ts` が外れていました。#92 では、`main.ts` の止まり方の判断の行が外れ、「テストが届かないものが 0 個」と報告しました。`.fallowrc.json` の `entry` に `src/main.ts` と `scripts/*.ts` を足し、`none-file` として出させます。`bun run check` が、dead code として外される変異がないことを確かめます。
- 既定では、ファイル・プロセス・ネットワークに触る関数を変異させません。このリポジトリでは、秘密情報の読み書き、作業ディレクトリ、`opencode.json` の書き込みなど、安全境界の多くがそれに当たります。`--allow-side-effects` で対象にすると、`writeOpencodeConfig` の「既存のファイルと中身が違えば起動しない」条件を変えても落ちないことが分かりました。変異させた関数が実際に書くので、`HOME` を `.local` の中に向けて動かし、外に書かないことを確かめました。
- 生き残りの型の検査（`--typecheck`）は、別のパッケージが TypeScript の JS の API を使うので、TypeScript 7 では動きません。
- 直近の 12 件の PR に当てると、変異 950 個のうち、生き残りは 176 個（うち文言の変異 60 個）、テストが届かないものは 154 個でした。`length > 0` を `length != 0` にする変異のような、等価な変異も含みます。
- fallow 全体は広く使われています（GitHub の星 5,400 ほど、数日おきにリリース）。ただし、ミューテーションの機能と `bun test` のランナーは 2026-10 に入ったばかりで、保守は実質 1 人です。

## 決めたこと

- 振る舞いを変えたら、PR を出す前に `bun run mutation` を走らせる。中身は `scripts/mutation.sh` で、`main` との差分の行に、`--allow-side-effects` を付けて `fallow mutation` をかける。`HOME` は `.local` の中に向ける。
- 生き残った変異と、テストが届かない変異（`direct`、`none-file`）は、テストで捕まえるか、捕まえない理由（等価、文言だけ、など）を PR に書く。
- CI では動かさない。失敗にもしない。生き残りのうち本物の穴の割合が分かっていないためと、等価な変異の扱いを決めていないため。
- fallow のバージョンは完全に固定する。上げるときは、384f1a7d で `!done` の変異が生き残ることを確かめる。
- 道具を替えるときは、`scripts/mutation.sh` だけを変える。

## 見直す条件

- `bun test` で動き、変異の種類が同じかそれ以上の、より成熟した道具が出たとき。
- fallow のミューテーションの機能が保守されなくなったか、破壊的に変わったとき。
- 生き残りを選り分ける手間が、見つかる穴の効用を上回る事例が続いたとき。
- 数件の PR で、本物の穴の割合が分かったとき。CI で一覧を出すか、検査にするかを決める。

## Considered Options

- **StrykerJS。** 最も成熟している。上のとおり、#78 の穴を捕まえず、Bun では回避が必要だった。
- **stryker-bun-runner。** Stryker の Bun のランナーのプラグイン。変異の種類は Stryker と同じで、利用も少ない。
- **mewt、mutie。** Rust 製などで JS/TS に対応するとされるが、利用が少ないか（mewt）、0.1.0 で互換性が限られる（mutie）。試していない。
- **Vitest だけに対応するもの（oxmutate など）。** `bun test` で動かない。
- **入れずに、文章の規則だけにする。** 本人の判定に頼る形のままで、#78 は規則があっても起きた。

## Consequences

- fallow が何も出さないことは、守られている証拠ではありません。fallow が見るのは、テストの中で動くコードの分岐です。子プロセスでだけ動くコードや、場面の組み合わせの不足は見ません。
- 型に合わない変異も、生き残りに混ざります。`tsc` で見分けます。
