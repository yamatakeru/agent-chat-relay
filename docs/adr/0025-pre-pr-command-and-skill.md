# PR を出す前の手順は、入口のコマンドと、プロジェクトの skill に置く

PR を出す前の規則は、`AGENTS.md` の「ミスの再発防止」の表に、文章で並んでいました。ミューテーションと e2e、「確認できなかったこと」の書き方、simplify とレビューの順です。このうち「確認できなかったこと」の規則は、PR #56、#78、#82、#92 で同じ形で破られました。どれも、その場面で規則が目に入らなかったことによります。`AGENTS.md` は常に読み込まれるので、ある場面でだけ必要な規則が増えるほど、どの規則も目に入りにくくなります。規則の置き場と、目に入る時を決めました（#96）。2026-11-20 に決めました。

## 分かったこと

**目に入るのが確実な順**

- 必ず通る場所に出すもの（コマンドの出力、検査のエラー）。読まずに先へ進めない。
- skill。説明（`description`）は常にモデルに見えるが、本文を読むかはモデルが決める。
- 常に読み込まれる文章（`AGENTS.md`）。

skill は、段としては文章のままです。読まなくても何も失敗しません。skill だけにすると、「規則を忘れる」が「skill を読み忘れる」に移るだけになりえます。

**ハーネスが skill を探す場所**（各ハーネスのドキュメントと、Harness Notes の比較を読んだ。2026-11-20。Codex、Cursor、OpenCode、Pi が `.agents/skills/` を読むことは、作業指示者が使っていて知っている）

- リポジトリの `.agents/skills/` は、Codex、Cursor、OpenCode、Pi が読みます。Claude Code は `.claude/skills/` だけを読みます。
- Cursor と OpenCode は両方を読みます。同じファイルにリンクで届く場合、Cursor は 1 つにまとめます。OpenCode は、名前が同じなら後に見つけたものを使います。
- `.claude/skills` を `../.agents/skills` へのリンクにすると、Claude Code（`claude -p`）が `pre-pr` を挙げることを確かめました。
- 中継が既定の作業ディレクトリで動かすハーネスには、このリポジトリの skill は届きません。作業ディレクトリを `git init` するので、Claude Code、Codex、Pi が上の階層を探すのは、そこで止まります。e2e と `scripts/relay.sh` の作業ディレクトリは、このリポジトリの `.local/` の下ですが、同じです。ただし、OpenCode（2.0.28）は、ファイルシステムの根まで探します。
- Claude Code の `CLAUDE.md` は、`git init` で止まらず、上の階層から読まれます。このリポジトリの `CLAUDE.md`（`@AGENTS.md`）も、`.local/` の下の作業ディレクトリに届きえます。中継は `claudeMdExcludes` でこれを除いています（ADR 0017）。
- 中継と同じ設定（`--setting-sources project,local` と `claudeMdExcludes`）で、`.local/` の下に `git init` したディレクトリから `claude -p` を動かし、`pre-pr` も `CLAUDE.md` の内容も文脈にないことを確かめました。`claudeMdExcludes` を外すと、`CLAUDE.md` の `@AGENTS.md` の行が見えました。

**数の書き写し**

#92 では、ミューテーションの出力を読んで数を書き写し、外れた変異を数え落としました。その結果、「テストが届かないものは 0 個」と書きました。

## 決めたこと

- **入口のコマンド。** `bun run pre-pr`（`scripts/pre-pr.ts`）が、テスト、検査、ミューテーションを走らせ、走らせる e2e を挙げます。そのうえで、PR 本文の「確認」と「確認できなかったこと」の下書きを、標準出力に出します。数と区分は実際の値で埋め、捕まえていない変異をファイルと区分ごとに挙げます。人が埋める欄は（）にします。コメントには、走らせたコミットを入れます。最後に skill の名前を出します。
- **e2e は走らせない。** 挙げて、結果の欄を作るだけにする。走らせ忘れはまだ起きておらず、時間と実費がかかるため。
- **skill。** 判断の部分は `.agents/skills/pre-pr/SKILL.md` に置きます。範囲（振る舞いか構造を変えた PR）、手順の順番、下書きの埋め方、「確認できなかったこと」の書き方と過去の失敗の例です。順番は、`pre-pr` で捕まえていない変異をテストで捕まえ、simplify とレビューをかけ、最後のコミットで `pre-pr` を走らせ直して下書きを得る、とします。テストを足したあとにも simplify とレビューがかかるようにするためです。`.claude/skills` は `../.agents/skills` へのリンクにします。
- **`AGENTS.md`。** 常に効かせる規則（秘密情報、`.local`、安全境界など）は残します。場面ごとの規則は skill に移し、表の行は skill と仕組みを指すだけにします。同じ規則を 2 か所に書きません。
- **`bun run mutation`。** 下の道具として残します。e2e の一覧は標準エラーに出し、`--format json` の標準出力を JSON だけにします。規則の文の表示はやめ、`pre-pr` の下書きと skill に移します。最後に、`pre-pr` と skill を指す 1 行だけを出します。`bun run mutation` を直接走らせても、skill に辿れるようにするためです。
- **（追記 2026-11-21）「確認できなかったこと」の区分を検査する。** 下の見直す条件の 1 つ目に当たりました。#106 では、手段（実際の Claude Code の Haiku とモックの LINE）と費用（5 分ほど）を規則どおりに書いたうえで、「安全境界でも節約の仕組みでもない」を理由に確かめませんでした。作業指示者に問われて 5 分で確かめると、意図した問いかけに黙るようになっていました（#107）。この節の自由な理由の欄では、確かめる価値を本人が判断し、省いたことを事後に報告で作業指示者へ渡せます。#104 の「ミューテーションの全件完了（数分、実費なし）」も同じ形でした。
  - 各項目に、区分を 1 つ書かせます。区分は、「実サービス」（実際のチャットサービス、アカウント、課金が必要）、「手段なし」、「承認 名前」（作業指示者が承認した）だけです。手元のハーネス、モック、偽物で確かめられるものに当たる区分は作りません。省くかの判断は、PR を出す前に作業指示者へ移します。
  - 区分の一覧と判定は、下書きと同じ `scripts/pr-draft.ts` に置きます。`bun run pr-body <本文のファイル>` を PR を作る前に手元で、同じコマンドを CI（`.github/workflows/pr-body.yml`、本文を直したときも）で走らせます。CI は、本文をイベントの JSON から読み、`run:` に式で埋め込みません。
  - 「確認できなかったこと」の節がない本文は通します。外部の PR を、このリポジトリの書き方で落とさないためです。
  - 過去の本文で確かめました。#106 の最初の本文は、実サービスの項目に区分を付けても、案内の項目で失敗します。#103 の 2 項目と、#104 の実サービスと指示の項目は、区分を付ければ通ります。

## 見直す条件

- 作ったあとの数件の PR で、「確認できなかったこと」の書き方や、simplify とレビューの順が、また破られたとき。文章より上の段（検査など）を探す。
- 挙げられた e2e の走らせ忘れが起きたとき。`pre-pr` で走らせる。
- （追記 2026-11-21）手元で確かめられるものを、実際と違う区分（「手段なし」など）で通す事例が出たとき。確かめる手段そのものを導く形（場面を与えると実際のハーネスで流す道具など）を探す。
- Claude Code が `.agents/skills/` を読むようになったとき。リンクを消す。

## Considered Options

- **`AGENTS.md` に文章で置いたままにする。** 4 回破られた形のまま。
- **skill だけにする。** 読むかをモデルが決めるので、場面に気づかない失敗が残る。
- **`bun run mutation` を広げる。** コマンドは増えないが、名前と中身がずれる。
- **（追記 2026-11-21）区分に「30 分を超える」などの時間を入れる。** 時間の見積もりは本人がするので、本人の判定に頼る形（ADR 0021 で外した形）に戻る。長いものは、作業指示者に聞いて「承認」にする。
- **（追記 2026-11-21）「確認」の節の「確かめていない」などの語を検査する。** #106 では、確かめた範囲の残りを「確認」の中の断り書きにしていた。ただし、語の検査は言い換えで通る（34054787 の判断と同じ）。skill に、残りは「確認できなかったこと」の項目にすると書く。
- **下書きを作らず、出力に skill の名前を足すだけにする。** 最小だが、数の書き写しの誤りが残る。
- **`pre-pr` で e2e を既定で走らせる。** 走らせ忘れが構造で起きなくなるが、毎回、時間と実費がかかる。

## Consequences

- 下書きの数が正しいことは、本文が正しい証拠ではありません。下書きが埋めるのは、道具の出す数と区分だけです。手段の区別、理由、e2e の結果は、人が埋めます。
- 下書きを作る `scripts/pr-draft.ts` は、fallow の JSON の形（`summary.counts`、`mutants[].status`、`test_reach`）に依存します。fallow を上げるときは、下書きが読めることを確かめます。
