# エージェントが返すファイルは、承認なしで、作業場所の中のものだけを送れる

チャット用ツールの `reply` に `files` を追加し、エージェントが画像などを添付して返信できるようにします（2026-11-09）。チャット用ツールは承認なしで使える（ADR 0008）ので、ファイルの送信にも承認を求めません。その代わり、中継は、送信できるファイルを作業場所（`.local/relay/workspace`）の中のものに限ります。

- 中継は、パスを実パスに解決してから確認します。作業場所の外を指すシンボリックリンクや `..` も拒否します。
- 送信できるファイルの種類は接続部が決めます。LINE では JPEG と PNG の画像（10MB まで）だけを、推測できない URL で 7 日間公開して渡します（ADR 0005）。

ADR 0005 は、画像の送信が Bash による実行で、送信のたびに承認が必要になることを前提にしていました。この ADR で、その前提を置き換えます。

## Considered Options

- **場所を制限しない。** 読めるファイルなら何でも送れる。ただし、作業場所の外（ホームディレクトリの中など）の画像も、承認なしで外部に出せてしまう。
- **送信のたびに承認を求める。** 意図しないファイルは送られない。ただし、送信のたびに承認者に Push が届き、LINE の通数も消費する。

## Consequences

- 作業場所の中身は、承認なしでルームに送れます。ただし、作業場所の中のファイルは現在でも承認なしで読んで `reply` の本文で送れるので、外部に出せるものの範囲は広がりません。受け取った添付ファイル（`.relay/inbox/`）も作業場所の中にあるので、別のルームに転送できます（ADR 0008 と同じく、プロンプトインジェクションで起こりえます）。
- エージェントが承認を得て作業場所の外からファイルをコピーすれば、そのファイルも送れます。コピーの操作に承認が必要なので、そこで止められます。
- 将来、作業場所の外のファイルも送れるようにする（設定で選べるようにする）余地を残します。その場合は、この ADR を改訂します。
