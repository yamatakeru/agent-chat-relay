# エージェントが返すファイルは、承認なしで、作業場所の中のものだけを送れる

チャット用ツールの `reply` に `files` を足し、エージェントが画像などを添えて返せるようにする（2026-11-09）。チャット用ツールは承認なしで使える（ADR 0008）ので、ファイルの送信にも承認を求めない。その代わり、中継が、送れるファイルを作業場所（`.local/relay/workspace`）の中のものに限る。

- 中継は、パスを実パスに直してから確かめる。作業場所の外を指すシンボリックリンクや `..` も拒む。
- 送れる種類は接続部が決める。LINE は JPEG と PNG の画像（10MB まで）だけで、推測できない URL で 7 日間公開して渡す（ADR 0005）。

ADR 0005 は、画像の送信が Bash の実行で、送るたびに承認が要ることを前提にしていた。この ADR で、その前提を置き換える。

## Considered Options

- **場所を限らない。** 読めるファイルなら何でも送れる。作業場所の外（ホームの中など）の画像も、承認なしで外へ出せてしまう。
- **送るたびに承認を求める。** 意図しないファイルは出ない。ただ、送るたびに承認者へ Push が届き、LINE の通数も使う。

## Consequences

- 作業場所の中身は、承認なしでルームへ出せる。ただ、作業場所の中のファイルは、今でも承認なしで読んで `reply` の本文で送れるので、外へ出せるものの範囲は広がらない。受け取った添付（`.relay/inbox/`）も作業場所の中にあるので、別のルームへ転送できる（ADR 0008 と同じく、プロンプトインジェクションで起こりうる）。
- エージェントが承認を得て作業場所の外からファイルを写せば、そのファイルも送れる。写す操作に承認が要るので、そこで止められる。
- 将来、作業場所の外も送れるようにする（設定で選べるようにする）余地を残す。そのときは、この ADR を改める。
