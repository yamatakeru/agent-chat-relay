# Discord は Gateway を discord.js で受信し、スレッドは親チャンネルの登録を引き継ぐ

Discord の接続部は、公式の Claude Code Discord プラグイン（`claude-plugins-official` の `external_plugins/discord`）を手本にします（2026-11-09）。Gateway（常時接続の WebSocket）で受信し、REST で送信します。どちらも discord.js（14.28.1）に任せます。これは、ADR 0007 で TypeScript を選んだ理由の 1 つでもあります。

## 決めたこと

- **受信方式**：Gateway で受信する。Webhook もトンネルも不要。再接続と REST の回数制限（ルートごとの待機）は discord.js が処理する。
- **ルームの ID**
  - チャンネルは `discord:c<ID>` で表す。
  - スレッドは `discord:c<親チャンネル>/<スレッド>` で表す。
  - DM は、LINE や Chatwork と同じく、相手の ID（`discord:u<ID>`）をルームの ID にする。
- **スレッド**
  - スレッドは別のルームとして扱い、返信はスレッドに送る。
  - 登録（受信モードと送信者の許可を含む）は、親チャンネルから引き継ぐ。中核は「ID が `親/子` の形式なら親の登録を参照する」とだけ決め、受信でも送信でも ID だけで判定する。
  - 未登録のチャンネルのスレッドで話しかけられた場合は、そのスレッドに、親を登録するためのコードを返す。
  - 送信は、実際の親チャンネルが ID に含まれる親と一致するスレッドにだけ行う。登録したチャンネルの ID に、ほかのチャンネルのスレッドを付けて送信されるのを防ぐため。
  - 公開スレッドは、Bot が参加していなくても受信できる。公式ドキュメント（`developers/topics/threads.mdx`）に「Upon connecting to the Gateway, apps will be automatically subscribed to thread events and active threads.」とある。非公開スレッドは、Bot を招待した場合にだけ受信できる。
- **メンション**：Bot への `@`、Bot 専用ロールへの `@`、Bot の発言への返信をメンションとして扱う。返信は、discord.js が返信先の送信者を格納する `mentions.repliedUser` で判定する（返信時に通知をオンにしたかどうかには依存しない）。`@everyone`・`@here`・ほかのロールへのメンションは含めない（GLOSSARY）。なお、プラグインは discord.js の既定の判定を使うので、`@everyone` もメンションとして扱ってしまう。
- **サーバーへの追加**：Bot がサーバーに追加されても、コードは投稿しない。追加先はサーバーなので、どのチャンネルを登録したいのかが分からないため。登録したいチャンネルで話しかければ、コードが返る。
- **Bot と Webhook による発言は受信しない**：Bot 同士が応答し続けるのを防ぐため（プラグインと同じ）。履歴には含まれる。
- **`fetch_messages`**：Discord の履歴を読む。Gateway は停止中の発言をあとから配信しないが、履歴からは読める。
- **送信**
  - 本文は 1 通 2,000 字までで、超える場合は 10 通まで分割して送る。
  - ファイルは種類を問わず、1 ファイル 10MiB、1 回 10 個までと申告する。現在の既定値は 10MiB で、サーバーのブーストで上限が上がる。プラグインにある 25MB は古い値である。
  - エージェントが書いた本文では、`@everyone`・`@here` やロールへの通知が飛ばないようにする（`allowedMentions`）。プロンプトインジェクションによって大勢に通知が飛ぶのを防ぐため。
- **実行承認**：承認者の DM に、許可・拒否のボタンを付けて送る。`yes <ID>`・`no <ID>` のテキストでも返事ができる。ボタンが押されたら、ボタンを外して結果を追記する。
- **テスト方法**：discord.js のイベントを偽の Client で流す単体テストと、実際の Discord で確認する。Gateway のモックは作らない。作成の手間が大きく、Discord は無料で、送信の通数の制約もないため。

## Considered Options

- **スレッドの親を接続部に問い合わせる**（ID はスレッドだけにする）。ID は短くなる。ただし、送信できるかどうかの判定が非同期になり、中核と接続部の間の取り決めが増える。
- **スレッドごとに登録する**。中核は今のままで済む。ただし、スレッドを作るたびに管理者の操作が必要になる。
- **Gateway のモックで e2e テストを作る**。LINE・Chatwork と同じ形で全体を通して確認できる。ただし、作成に手間がかかる。

## Consequences

- 中核の `access.ts` に `registrationOf` を追加しました。`親/子`（どちらも空でなく、`/` が 1 つだけ）の形式なら親を返し、それ以外の形式は登録と一致させません。
- 中核は ID の文字列しか見ません。入れ子の ID を使う接続部は `nestedRooms` を申告し、送信時に、子が実際にその親に属しているかを確認します。申告していない接続部には、`/` を含む ID で送信しません。ほかのサービスに入れ子の場があれば、同じ取り決めで扱えます。
- 依存関係に discord.js が加わります。
- Discord Developer Portal で、Message Content の特権インテントをオンにする必要があります。Bot の利用者が 1 万ユーザー未満のうちは、審査は不要です（2026-06 の変更）。
- 停止中の発言は、中継の記録にも残りません。`fetch_messages` で Discord の履歴から読みます。
