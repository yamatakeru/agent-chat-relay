# LINE も cc-connect 標準の LINE platform ではなく、Bridge 経由の自作アダプターで接続する

> ADR 0006 で cc-connect の利用をやめ、自作の中核が ACP でハーネスを動かす構成に置き換えました。

> cc-connect との接続方式（Bridge）は、ADR 0003 で cloud_web に置き換えました。アダプターを自作するという判断は変わっていません。

本番では、グループでメンションされたときだけ反応させたいと考えています。しかし cc-connect v1.5.0 の LINE platform には、Feishu・Slack・Discord などにある `group_reply_all = false` に相当する設定がなく、グループのすべての発言に反応してしまいます。本体に PR を出すことも考えましたが、未処理の PR が 300 件を超えており、LINE の改善 PR #854 も半年間取り込まれていないため、早期の取り込みは見込めません。fork を保守し続けることも避けたいところです。そこで、LINE WORKS・Chatwork と同じ Bridge 基盤の上に、LINE のアダプターを自作します。標準の LINE platform は、まず検証で実際の挙動を確かめるために使います。その検証で別の致命的な問題が見つかった場合は、この判断を見直します。

## Considered Options

- 本体に PR を出し、取り込まれるまで標準の LINE platform で待つ。自前のコードは最小限で済むが、本番に投入できる時期が読めない。
- PR を出しつつ、自前の fork で運用する。すぐに使えるが、取り込まれるまで fork の保守が続く。

## Consequences

- メンションの判定、Reply を優先して期限切れなら Push で返す返信方式、将来の承認者の制限を、アダプター側で実装できます。
- Bridge の制約を受け入れることになります。メッセージには到達確認（ACK）がなく、切断中の返信は失われ、`allow_from` もありません。返信が失われた可能性があるときはルームに通知し、送信者の許可はアダプター側で判定します。
- v1.5.0 では、ネイティブの platform がないプロジェクトは起動できません。これを回避する手段が必要です。
- 本体の LINE platform に同等の設定が追加された場合は、標準の platform に戻すことを再検討します。
