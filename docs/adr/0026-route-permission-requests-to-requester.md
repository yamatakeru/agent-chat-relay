# 承認依頼は、依頼者が 1 人に決まれば、その人だけに送る

実行承認の依頼は、許可リストの全員の DM に届き、だれでも答えられました。そのため、関係のない人にも依頼が届き、だれの依頼で、どのルームの話かも分かりませんでした。ある人の依頼を、別の人が中身を知らずに許可することもできました（#29）。送り先は未決のままでした（#62）。中継は、ターンに渡した発言とその送り手を知っています。一方、どの発言がきっかけで承認依頼が出たかは、ACP の承認依頼（`session/request_permission`）には入っていません。モデルの中にしかなく、だれも決定論的には知りません。そこで、ターンの構成から決定論的に送り先を決め、決まらない場面だけ、判定に特化したモデル（Jev）の確率で補うことにしました。2026-11-20 に作業指示者と決めました。

## 決めたこと

- 承認依頼が届いた時点で、そのターンに渡した発言（差し込んだ発言と、受信モードが「すべて」のルームのメンションのない発言を含む）の送り手を見る。依頼のあとに届いた発言は入れない。
  - 送り手が 1 人だけで、その人が承認者なら、その人だけに送る。答えを受け付けるのも、その人からだけにする。
  - 送り手が複数いて、その中に承認者がいれば、Jev に判定させる（有効なときだけ）。判定した確率が下限（既定 0.8）以上で、選ばれた人が承認者なら、その人だけに送る。
  - それ以外は、今までどおり全員に送る。ターンの外で届いた依頼、送り手に承認者がいない、Jev が無効・失敗した・2 秒を超えた・下限に届かない、のどれかの場合。
- 全員に送るときは、文面に、そのターンの発言のルームと送り手を、「依頼者」（メンションした人）と「そのほかの発言」に分けて並べる。どの発言による依頼かは分からないと書く。ターンの外の依頼には書かない。
  - 名前は、送った人やルームの持ち主が決められる。改行と制御文字を空白に置き換え、名前は 40 字まで、一覧は 300 字までにして、超えた分は「ほか N 人」にまとめる。偽の答え方を文面に紛れ込ませないため。
- 1 人に送る文面には、その人の発言による依頼として、その人だけに送ったことを書く。Jev で決めたときは、確率も書く。
- 1 人に送った依頼に答えがなくても、全員には広げない。今までどおり、ルームに承認待ちを知らせ（ADR 0024）、30 分で拒否する。
- 受け取り手の違う依頼は、同じ束（ADR 0014）に入れない。受け取り手が変わったら、今の束を先に送る。答えていない束を出し直すときは、その人が答えられる束だけを出す。
- 送ったあとに、受け取り手が許可リストから外れたら、その束は全員が答えられるものとして扱う。
- Jev（TypeSafe AI の System One モデル）は、管理者が API キー（`RELAY_TYPESAFE_API_KEY`）を `secrets typesafe` で保存したときだけ使う。
  - 渡すのは、そのターンの発言（送り手の名前、ルームの名前、本文）、そのターンでエージェントが書いた文、承認依頼の題名と入力。どれも長さを切る。
  - モデルは `jev-1.14.0` に固定する。別名（`jev-latest`）は指す先が変わり、下限を合わせた確率の意味が変わるため。
  - 下限は `RELAY_JEV_MIN_PROBABILITY`（0 より大きく 1 以下）で変えられる。範囲の外なら起動しない。
  - 判定の結果と確率、失敗をログに書く。

## Considered Options

- **文面に候補を並べるだけにする。** 小さく、外部に依存しない。ただし、送り先も答えられる人も変わらず、#29 は解けない。全員に送るときの文面として残した。
- **別の人の発言を、承認依頼が出うる間は差し込まずにためる。** 帰属を保証できる。ただし、作業中の発言を差し込む利点（ADR 0018）を削り、待ち行列が詰まる。
- **承認依頼の受け取り手を、許可リストとは別に設定する**（OpenClaw の `approvals`、#6535 の案）。決定論的で小さい。ただし、依頼者に届ける問題は解かない。必要になれば、この規則と独立に足せる。
- **ハーネスのプラグインで送り先を決める。** ハーネスはチャットの人を知らず、帰属も得られない。ハーネスごとに作る必要があり、ハーネスとは ACP と MCP だけでつなぐ方針にも合わない。
- **送り手が 1 人のターンでも Jev に確かめさせる。** 前のターンの続きやバックグラウンドの処理による依頼に気づける。ただし、承認依頼のたびに外へ送り、決定論的に決まる場面を確率で揺らす。
- **Jev に送り先を決めさせず、文面に判定を書くだけにする。** 外れても送り先は変わらない。ただし、全員に届く問題は解けない。外れたときの害は、許可リストの 1 人に届くことにとどまり（その人は今でも許可できる）、広がらないので、送り先に使うことにした。

## Consequences

- 前のターンで頼まれた作業の続きや、バックグラウンドのタスク・サブエージェントが出した依頼も、今のターンの送り手が 1 人なら、その人に届きます。Claude Code は、ターンの外でも自分で処理を始めることがあります（ACP のアダプターの autonomous cycle）。その依頼が、ちょうど始まったターンの 1 人に届くこともあります。入力は文面に出ており、答えなければ 30 分で拒否になります。
- 1 人に送った依頼には、ほかの承認者の目が入りません。依頼者が自分で許可することになります（今までもできました）。
- 帰属を根本から保証するには、ルームごとにセッションを分ける必要があります（#64）。互いを信頼しない集団には中継を分ける、という前提（`docs/relay.md`）は変えません。
- Jev を有効にすると、ルームの発言とツールの入力（秘密情報が入りうる）を TypeSafe AI に送ります。TypeSafe AI は、送られたデータを学習に使いません。送ったデータを答えのあとすぐに消す設定（ZDR）は、どの組織でも無料で、サポートに申請すると有効になります（2026-11-21 に TypeSafe AI のヘルプで確認。この ADR の決定時は enterprise 向けと書いていた）。
- Jev は日本語より英語の精度が高いとされます。下限は、実際の記録で確かめて調整します。
