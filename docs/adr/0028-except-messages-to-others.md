# 他人宛ての発言は、受信モードで外せるようにする

受信モードには「メンション時」と「すべて」しかありませんでした。「すべて」では、ほかの人どうしのやりとりもすべてエージェントに渡り、そのたびにターンが起きて、必要以上にトークンを使います。「メンション時」では、会話の流れがエージェントに届きません。その中間がほしい、という要望がありました（#105）。また、「すべて」のルームで、どの発言が自分宛てかの判断はエージェントに任せていましたが、その材料（メンションかどうか）も渡していませんでした。2026-11-21 に作業指示者と決めました。

## 決めたこと

- 受信モードに「他人宛てを除く」を足す。他人宛ての印があり、Bot へのメンションがない発言は、エージェントに渡さず、記録だけする。
  - 印になるのは、Bot でも送信者でもない人へのメンション、Bot 専用でないロールへのメンション（Discord）、その人の発言への返信・引用。
  - 全員宛て（Chatwork の `[toall]`、Discord の `@everyone`・`@here`、LINE の全員へのメンション）は、印にしない。
  - 返信の機能でない引用（Chatwork の `[qt]`）は、印にしない。引用した文を載せるだけで、相手には宛てていない。「この発言をどう思う？」のように、Bot への問いにも使われる。LINE の引用は返信の機能なので、印にする。
  - 返信・引用は、引用元の送信者が分かるときだけ印にする。LINE は、引用元を中継が受けていなければ（再起動の前の発言など）、印にしない。「記録にない引用は他人宛て」とすると、再起動のあとに Bot への返信を落とすため。
  - Bot と他人の両方へのメンションは、Bot 宛てとして渡す。
  - 話題として他人をメンションしただけの発言（「@田中 の件どう思う？」）は外れる。Bot にメンションし直せば渡る。困るようになったら、別に扱いを決める。
- 印のない発言を Jev（ADR 0026）で判定して外すモード「他人宛てを除く（Jev）」も足す。問いとしきい値は、日本語のダミーの会話を実際の API に通して確かめてから決める。
  - 1 発言につき 1 回問い合わせ、yes/no の問い（Noul）を 3 つ載せる。エージェントに向けた発言か、エージェント以外の特定の人に向けた発言か、エージェントが直前にした問いや依頼に答えた発言か。TypeSafe AI の推奨（1 つの問いに 1 つの条件、組み合わせはコードで）に従う。
  - 外すのは、2 つ目の確率が高く、1 つ目と 3 つ目の確率がどちらも低いときだけ。問いとしきい値は、コードの 1 か所に定数で置き、環境変数にはしない。問いとしきい値は、組で意味を持つため。
  - 渡すのは、サービス名、ルーム名、Bot の表示名、同じルームの直前の発言（Bot の発言と外した発言を含む。件数は `RELAY_JEV_CONTEXT_MESSAGES`、既定 10、0〜30）、判定する発言。本文は 1 件 1,000 字まで。人には p1, p2… の名前と表示名を付け、ID は送らない。
  - Jev が失敗した・2 秒を超えたときは、渡す。API キーがないときは、起動時と受信モードを変えるときに警告し、「他人宛てを除く」と同じに動く。
  - Jev に問い合わせるのは、このモードを選んだルームだけ。API キーを置くこと（ADR 0026 の同意）だけでは、ルームの発言を送らない。
  - 問い合わせは受け取ったときに始め、答えを待つあいだも発言の順番は保つ（後ろのメンションも最大 2 秒待つ）。受け取りの合図は、今どおりすぐに出す。
- 外した発言は、ターンを起こさず、作業中のターンにも差し込まない（ADR 0018 で「あらためて決めます」とした、差し込む発言を絞ることに当たる）。記録には残すので、エージェントは `fetch_messages` で読める。ログには、本文を書かずに、ルームと理由（Jev なら確率も）を書く。
- エージェントに、判断の材料を渡す。
  - メンション（DM を含む）の `<message>` に `mentioned="true"` を付ける。
  - `list_rooms` の各ルームに、受信モードを書く。
  - 案内に、`mentioned` のない発言には必要なときだけ返事すること、ルームによっては一部の発言だけが届くので、流れが必要なら `fetch_messages` で読むことを書く。
- 受信モードは、`access.json` のルームの `receive`（`mention`・`exceptOthers`・`exceptOthersJev`・`all`）に持つ。
  - 古い形（`requireMention`）は読み替える（true は `mention`、false は `all`）。保存するときは `receive` だけを書く。
  - 知らない値は「メンション時」として扱い、ログに書く。受信のたびに読み直すので、起動を止めると、書き損じで動いている中継が止まるため。
  - 管理者は `access mode <番号か ID> <受信モード>` で変える。番号は `access` の一覧のもの（一覧は ID を伏せるため）。
- これは費用を抑えるためのフィルターで、安全境界ではない。細工した発言でできるのは、自分の発言をエージェントに渡すこと（「すべて」と同じ）か、他人の発言を落とすこと（メンションし直せば渡る）までで、ルームの登録・送信者の許可・実行承認は変わらない。

## Considered Options

- **何もしない（今の「すべて」）。** 要望を解かない。
- **判断の材料をエージェントに渡すだけにする。** 自分宛てでない発言に黙れるようにはなる。ただし、ターンは起きるので、入力のトークンはほとんど減らない。外す仕組みと組み合わせて採った。
- **構造だけで外す。** 決定論的で、外部に送らない。ただし、本文の中の暗黙の呼びかけや、宛先のない雑談は外せない。「他人宛てを除く」として採り、それを補うモードとして Jev を足した。
- **すべての発言を Jev で判定する。** 暗黙の呼びかけも外せる。ただし、構造で決まる発言まで外部に送り、確率で揺らす。ADR 0026 と同じく、決定論的に決まらない発言だけを Jev に回すことにした。
- **別の LLM やハーネスに判定させる。** 柔軟だが高い。ハーネスとは ACP と MCP だけでつなぐ方針（ADR 0006）にも合わない。
- **外した発言をため、次のターンの前置きにまとめて渡す。** ターンを起こさずに、会話の流れを渡せる。ただし、ためる上限と渡し方を決める必要がある。今は `fetch_messages` で読めるので、将来の検討とした。
- **外した発言も、作業中のターンには差し込む。** 流れがその場で入る。ただし、外した発言で作業が中断され、トークンも使う。
- **ためた発言を、時間や件数でまとめて要約させる。** 結局ターンを起こすので、節約にならない。
- **Jev のしきい値を環境変数にする（ADR 0026 と同じ形）。** 管理者が調整できる。ただし、問いとしきい値は組で意味を持ち、片方だけ変えると意味がずれる。記録を見て、コードで直す。
- **知らない受信モードがあれば起動しない。** 書き損じに確実に気づく。ただし、`access.json` は受信のたびに読み直すので、動いている中継での扱いを別に決める必要がある。

## Consequences

- 「他人宛てを除く」のルームでは、他人宛ての印がない雑談は、今までどおりエージェントに渡り、ターンを起こします。外せるのは印のある発言だけです。
- 外した発言は、`fetch_messages` で読めます。ただし、LINE と Chatwork では中継のメモリの記録だけなので、再起動すると消えます（#65）。
- 「他人宛てを除く（Jev）」を選んだルームでは、印もメンションもない発言と、その前の発言（件数は設定による）を TypeSafe AI に送ります。送る範囲は、承認依頼のとき（ADR 0026）より大きく広がります。
- 承認依頼の送り先（ADR 0026）は、そのターンに渡した発言の送信者で決めるので、外した発言の送信者は入りません。
