# cc-connect をやめ、自作の中核が ACP で任意のハーネスを動かす

cc-connect は、接続する側が主になる作りである。チャットごとにセッションを作り、返事は発言のあったチャットへ自動で返す。私たちが求めるのは、その逆である。

- 複数のルームを 1 つのセッションにまとめる。
- エージェントが、ほかのルームの様子を読み、ほかのルームへ投稿する。

cc-connect の上でこれを実現しようとすると、回避策が増え続ける。すでに次のことをしている。

- 承認の依頼を、cc-connect が人向けに書いた文章から読み取る。
- cc-connect の案内やコマンドを塞ぐ。
- 内部ファイル（作業場所の割り当て）に直接書く。

Claude Code のチャンネル（公式の Discord プラグイン）は、目指す役割の分け方を示している。セッションが主で、接続部分は発言を届けることと、送信のツールを渡すことだけを担う。ただし、発言をセッションに押し込む仕組みと、承認を中継する仕組みは Claude Code に固有で、ほかのハーネスでは使えない。

そこで、cc-connect をやめ、次の形で自作する（2026-11-09）。

- **中核**（Go）が、サービスごとの接続部を持つ。中核の担当は、受信、ルームの登録、送信者の許可、送信の待ち行列、発言の記録。
- **チャット用ツールは MCP で渡す。** `reply`、`fetch_messages` などを、どのハーネスにも同じ形で渡す。
- **押し込みは ACP だけで行う。** 中核が ACP のクライアントとしてハーネスを起動する。
  - `session/new` でチャット用ツールの MCP サーバーを渡す。
  - `session/prompt` で発言を入れる。作業中に届いた発言はためておき、ターンが終わったらまとめて入れる。
  - `session/request_permission` で受けた実行承認の依頼を、ルームへ回す。返事は、許可した送り主からのものだけを通す。
- **Claude Code も ACP で動かす。** ACP の公式組織が保守する `claude-agent-acp` を使う。Claude Code のチャンネルは使わない。経路を 1 つにするため。
- **セッションは、まず 1 つにする。** 登録したルームを、1 つのセッションにまとめる。セッションを分けたうえで、互いの記録をツールで見せる形にも移れるようにしておく。

## Considered Options

- **cc-connect に乗り続ける。** チャットサービスやエージェントの種類、cron などの機能は揃っている。ただ、セッションの分け方が逆で、回避策が増え続ける。
- **Claude Code のチャンネルだけで組む。** 今の使い心地のままで、最もコンパクト。ただ、Claude Code にしか使えない。研究段階の機能で、自作のチャンネルには開発用のフラグ（`--dangerously-load-development-channels`）が要る。
- **チャンネルと ACP の両方で押し込む。** 端末の画面で Claude Code を見ながら使える。ただ、ACP は Claude Code にも対応しているので、経路が増えるだけになる。
- **OpenClaw や Hermes Agent に乗る。** これらはそれ自体がハーネスで、チャットとハーネスの間をつなぐ部品ではない。

## Consequences

- ADR 0001・0003・0004 を置き換える。ADR 0002（Go）と ADR 0005（画像の公開）は引き継ぐ。画像は、`cc-connect send` ではなく、チャット用ツールで返すことになる。
- cc-connect の実装と記録は `old/` に移した。LINE の仕様の判断（`old/docs/line-adapter.md`）は、新しい実装でも参照する。具体的には、受信モード、承認の言葉、Reply トークンを優先する送信、画像とファイルの扱い。
- cc-connect の cron、各種コマンド、表示モードなどは使えなくなる。要るものだけを作る。
- **ルームごとに作業場所と会話を分ける仕組み（仕様 D）はなくなる。** 1 つのセッションにまとめたルームでは、会話もファイルも互いに見える。まとめるのは、信頼できる人のルームだけにする。範囲を分ける必要が出たら、中核とハーネスの組を分けて動かす。
- **防壁は、これまでどおり実行承認。** ハーネスの設定の読み込み（Claude Code の `--setting-sources` に当たるもの）を、ACP のアダプターでどう指定するかを確かめる。
- ハーネスは画面なしで動く。端末から話しかける必要が出たら、端末用の接続部を足す。
- `claude-agent-acp` は Agent SDK の上に作られている。自分のプランでログインして使う場合、利用量は通常のサブスクリプションの枠から引かれる（Claude のヘルプセンター、2026-10-07 更新）。
- ACP には v1 と v2 がある。アダプターが話す版に合わせる。
