# cc-connect をやめ、自作の中核が ACP で任意のハーネスを動かす

cc-connect は、チャット側が主体になる設計です。チャットごとにセッションを作り、返信は発言のあったチャットに自動で返します。私たちが求めているのは、その逆です。

- 複数のルームを 1 つのセッションにまとめる。
- エージェントが、ほかのルームの様子を読み、ほかのルームに投稿する。

cc-connect の上でこれを実現しようとすると、回避策が増え続けます。すでに次のような回避策を入れています。

- 承認の依頼を、cc-connect が人向けに書いた文章から読み取る。
- cc-connect の案内やコマンドを無効にする。
- 内部ファイル（作業ディレクトリの割り当て）に直接書き込む。

Claude Code のチャンネル機能（公式の Discord プラグイン）は、目指す役割分担の手本になります。セッションが主体で、接続部分は発言を届けることと、送信用のツールを渡すことだけを担います。ただし、発言をセッションに送り込む仕組みと、承認を中継する仕組みは Claude Code 固有のもので、ほかのハーネスでは使えません。

そこで、cc-connect の利用をやめ、次の構成で自作します（2026-11-09）。

- **中核**（Go）が、サービスごとのコネクターを持つ。中核が担当するのは、受信、ルームの登録、送信者の許可、送信キュー、発言の記録。
- **チャット用ツールは MCP で渡す。** `reply`、`fetch_messages` などを、どのハーネスにも同じ形で渡す。
- **発言の送り込みは ACP だけで行う。** 中核が ACP のクライアントとしてハーネスを起動する。
  - `session/new` で、チャット用ツールの MCP サーバーを渡す。
  - `session/prompt` で発言を渡す。処理中に届いた発言はためておき、ターンが終わったらまとめて渡す。
  - `session/request_permission` で受けた実行承認の依頼をルームに転送する。返事は、許可した送信者からのものだけを受け付ける。
- **Claude Code も ACP で動かす。** ACP の公式組織が保守している `claude-agent-acp` を使う。経路を 1 つにするため、Claude Code のチャンネル機能は使わない。
- **セッションは、まず 1 つにする。** 登録したルームを 1 つのセッションにまとめる。将来、セッションを分けたうえで互いの記録をツールで参照する形にも移行できるようにしておく。

## Considered Options

- **cc-connect を使い続ける。** チャットサービスやエージェントの種類、cron などの機能は揃っている。ただし、セッションの分け方が逆なので、回避策が増え続ける。
- **Claude Code のチャンネル機能だけで構成する。** 今の使い勝手のままで、最もコンパクト。ただし、Claude Code でしか使えない。研究段階の機能で、自作のチャンネルには開発用のフラグ（`--dangerously-load-development-channels`）が必要。
- **チャンネル機能と ACP の両方で発言を送り込む。** ターミナルの画面で Claude Code を見ながら使える。ただし、ACP は Claude Code にも対応しているので、経路が増えるだけになる。
- **OpenClaw や Hermes Agent を使う。** これらはそれ自体がハーネスであり、チャットとハーネスの間をつなぐ部品ではない。

## Consequences

- ADR 0001・0003・0004 を置き換えます。ADR 0002（Go）と ADR 0005（画像の公開）は引き継ぎます。画像は、`cc-connect send` ではなく、チャット用ツールで返すことになります。
- cc-connect の実装と記録は `old/` に移しました（のちに削除しました。タグ `cc-connect-final` で参照できます）。LINE の仕様に関する判断（`old/docs/line-adapter.md`）は、新しい実装でも参照します。具体的には、受信モード、承認の言葉、Reply トークンを優先する送信、画像とファイルの扱いです。
- cc-connect の cron、各種コマンド、表示モードなどは使えなくなります。必要なものだけを作ります。
- **ルームごとに作業ディレクトリと会話を分ける仕組み（仕様 D）はなくなります。** 1 つのセッションにまとめたルームでは、会話もファイルも互いに見えます。まとめるのは、信頼できる人がいるルームだけにします。範囲を分ける必要が出てきたら、中核とハーネスの組を分けて動かします。
- **安全策は、これまでどおり実行承認です。** ただし、チャット用ツールは承認なしで使えます（ADR 0008）。ハーネスの設定の読み込み（Claude Code の `--setting-sources` に当たるもの）を、ACP のアダプターでどう指定するかは確認が必要です。
- ハーネスは画面なしで動きます。ターミナルから話しかける必要が出てきたら、ターミナル用のコネクターを追加します。
- `claude-agent-acp` は Agent SDK の上に作られています。自分のプランでログインして使う場合、利用量は通常のサブスクリプションの枠から消費されます（Claude のヘルプセンター、2026-10-07 更新）。
- ACP には v1 と v2 があります。アダプターが対応しているバージョンに合わせます。
