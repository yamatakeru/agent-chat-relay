# 受け取りの合図は、いつ出すかを中核が決め、どう出すかをコネクターが決める

中継がメンションを受け取ったことは、エージェントの返事が届くまで、依頼者には分かりませんでした（#24）。返事は、ハーネスの処理と実行承認を待つので、時間がかかることがあります。そこで、受け取ったらすぐに受け取りの合図を出すことにします（2026-11-15）。

チャットサービスによって、使える手段が違います。

- Discord：発言にリアクションを付けられる。入力中の表示も出せる。
- LINE：Bot が発言にリアクションを付ける API はない。既読を付ける API（`POST /v2/bot/chat/markAsRead`）と、1 対 1 のトークでのローディングの表示はある。既読を API で付けるには、OAM の［応答設定］で［チャット］をオンにする必要がある。オフのときは、LINE が受けた時点で既読が自動で付く。
- Chatwork：リアクションの API はない。既読を付ける API はあるが、ほかの人には見えない。

## 決めたこと

- いつ出すかは、中核が決める。合図を出すのは、エージェントに渡すメンションだけ（1 対 1 のトークと DM の発言を含む）。メンションのない発言（受信モードが「すべて」のルーム）、承認の返事、停止中に届いた発言には出さない。中核は `receive` の結果で、合図を出すかどうかをコネクターに伝える。
- どう出すかは、コネクターが決める。手段は、発言に付く通知の鳴らない印を優先し、なければルームに出る一時的な表示を使う。文章の送信は使わない。
  - Discord：👀 のリアクションを付け、入力中の表示を出す。
  - LINE：既読を付け、1 対 1 のトークではローディングの表示も出す。そのため、［チャット］はオンにする。
  - Chatwork：合図を出さない。
- 合図は、受け取ったときに 1 回だけ出す。返事が済んでも、外したり変えたりしない。
- 合図を出せなくても、発言はそのままエージェントに渡す。失敗はログに書くが、同じ失敗を発言のたびには書かない。
- 合図を止める設定は作らない。

## Considered Options

- **LINE で、文章で知らせる。** グループでも確実に見える。ただし、本番の返事に使うはずの Reply トークンを使ってしまう。そうなると返事が Push になり、グループではメンバーの人数分の通数を使う。
- **LINE で、Reply トークンの期限が切れる直前に、まだ使っていなければ一言返す。** 通数は増えない。ただし、合図が出るのは受け取ってから 40 秒ほどあとになり、すぐには知らせられない。
- **LINE で、［チャット］をオフのままにする。** 手順は変わらない。ただし、既読は LINE が受けた時点で付くので、中継が受け取ったかどうかは分からない。［チャット］をオンにすると、中継が止まっているあいだの発言は未読のまま残る。
- **Chatwork で、`[rp]` で一言返す。** 合図は確実に見える。ただし、発言のたびにルームの投稿が 1 通増え、ルームごとの投稿の制限（10 秒に 10 回）も使う。合図が届くのは、ポーリングの間隔（既定 5 秒）の分だけ遅れる。
- **返事が済んだら合図を外す・変える（Discord で 👀 を ✅ にするなど）。** Discord では分かりやすい。ただし、LINE の既読は外せないので、サービスによって合図の意味がずれる。

## Consequences

- LINE では、OAM の［チャット］をオンにします。OAM の画面から、人が手で返事をできる状態になります。
- LINE のグループの発言にも既読トークン（`markAsReadToken`）が付くかどうかは、まだ実サービスで確かめていません。付かない場合のグループの扱いは、その時点で決めます。
- Discord では、チャンネルに Add Reactions の権限が必要です。
- エージェントが使う `react`（チャット用ツール）とは別の機能です。`react` は、エージェントが自分の判断で使います。
