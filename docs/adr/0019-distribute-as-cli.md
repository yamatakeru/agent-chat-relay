# 中継を、どこからでも起動できる CLI として配布する

中継は、リポジトリを clone し、その中の `scripts/relay.sh` で起動するものでした。`relay.sh` はリポジトリ直下に移ってから動くので、中継のデータ（`.local/relay`）と秘密情報（リポジトリ直下の `.env`）は、必ずリポジトリの中に置かれました。

ADR 0017 で、作業ディレクトリとハーネスの設定の読み込みを、環境変数で選べるようにしました。しかし、普段のフォルダで使うたびに環境変数を指定するのは、取り回しが悪いものでした。そこで、中継を npm のパッケージとして配布し、どのディレクトリからでも起動できる CLI にすることにしました（2026-11-18）。

## 分かったこと

**Bun が自動で読むファイル**（Bun 1.4.4 の実機）

- Bun は、プログラムを起動したディレクトリ（cwd）にある次のファイルを、自動で読みます。`#!/usr/bin/env bun` で起動した場合も同じです。
  - `.env`：中身を環境変数に設定します。
  - `bunfig.toml`：`preload` に書いたコードを、本体より先に実行します。
- `bun --no-env-file --config=<ファイル>` で起動すると、どちらも読みません。`--config` に `/dev/null` を指定しても動きます。
- 中継は、`claude-agent-acp` を `bun` で起動していました。その cwd は作業ディレクトリです。そのため、作業ディレクトリの `.env` が、アダプターの環境変数になり、Claude Code にも引き継がれていました。
  - `RELAY_WORKSPACE` で `.env` のあるプロジェクトを指定すると、その値（`ANTHROPIC_API_KEY` など）が Claude Code に渡ります（ADR 0017 から）。
  - 既定の作業ディレクトリでも、エージェントが `.env` か `bunfig.toml` を書けば、次の起動からアダプターの環境やコードを変えられます。ただし、書くには実行承認が要ります。
- `claude-agent-acp` の場所は、起動したディレクトリを起点に `node_modules/…` として解決していました。インストールした形では見つかりません。

**似たツールの秘密情報の置き場**（2026-11-18 の検索）

- Claude Code 公式の Discord プラグインは、Bot のトークンを `~/.claude/channels/discord/.env` に平文で置きます。
- GitHub CLI は、OS の資格情報ストアを既定にし、使えなければ `~/.config/gh/hosts.yml` に平文で置きます。npm（`~/.npmrc`）や AWS CLI（`~/.aws/credentials`）も、ホームの下に平文で置きます。
- Bun の `Bun.secrets`（OS のキーチェーン）は、実験段階の API です。Linux では Secret Service が動いている必要があり、画面のないサーバーでは使えないことが多いです。

## 決めたこと

- npm のパッケージ `agent-chat-relay` として配布する。コマンドは `agent-chat-relay` で、別名を `ac-relay` とする。実行には Bun が必要（`engines.bun`）。
  - `bun build --compile` の単一のバイナリにはしない。アダプターを別のプロセスとして起動しているため。
- サブコマンドは、`serve`、`pair`、`access`、`secrets <line|chatwork|discord>`、`line-tunnel`、`line-quota` とする。
  - `line-tunnel` は、PATH 上の `cloudflared` を使う。
  - `line-webhook`（署名付きの Webhook をローカルへ送る）は開発用なので、CLI には入れない。
- **データの置き場**：既定は `~/.agent-chat-relay/` とし、`RELAY_HOME` で変えられる。起動したディレクトリには左右されないようにする。ルームの登録、許可リスト、秘密情報は Bot ごとのもので、プロジェクトごとのものではないため。
- **秘密情報**：
  - `<RELAY_HOME>/.env` に平文で置き、権限を 0600 にする。`RELAY_ENV_FILE` で変えられる。
  - 環境変数があれば、そちらを優先する。
  - `secrets` は、値を画面の入力から受け取り、表示しない。パイプからも読める。
  - 読み込むときに、自分以外も読める権限になっていたら知らせる。
- **作業ディレクトリ**：既定は、今までどおり `<RELAY_HOME>/workspace` で、中継が作り、`git init` する。起動したディレクトリを、既定で作業ディレクトリにはしない。
  - `serve` に `--workspace <dir>`、`--harness-settings default`、`--harness-memory` を足す。それぞれ、`RELAY_WORKSPACE`、`RELAY_HARNESS_SETTINGS`、`RELAY_HARNESS_MEMORY` の別名で、環境変数より優先する。3 つは独立していて、扱いは ADR 0017 のとおり。
  - 普段のフォルダで使うには、`agent-chat-relay serve --workspace .` のように明示する。
- **設定を読む場所**：起動したディレクトリと作業ディレクトリからは、中継の設定を読まない。どちらも、エージェントが書ける場所か、clone したリポジトリのように、管理者以外が用意した内容を含みうる場所だから。安全境界を緩める指定は、フラグと環境変数、`<RELAY_HOME>` の中だけで受け付ける。
- **Bun に cwd のファイルを読ませない**：
  - 中継の本体は、`bun --no-env-file --config=/dev/null` で起動する。配布物の `bin` は、そのように Bun を呼ぶシェルスクリプトにする。
  - `claude-agent-acp` も同じ指定で起動する。場所は、パッケージの依存から解決する（`import.meta.resolve`）。
- **開発**：`scripts/relay.sh` は、開発用のラッパーとして残す。
  - データの置き場は今までどおり `.local/relay`、秘密情報はリポジトリ直下の `.env`（dotenvx で暗号化）とする。
  - `secrets` は、dotenvx で暗号化する今の実装のまま。それ以外のコマンドは、中継の本体を呼ぶ。dotenvx で読み込み済みのときは、本体は秘密情報のファイルを読まない（`RELAY_ENV_LOADED`）。
- **既存のデータ**：自動では移さない。インストールした CLI に移るときの手順を、文書に書く。
- npm への公開は取り消せないので、公開の前に `npm pack --dry-run` で中身（`.env`、`.local`、`test` が入らないこと）を確かめる。

## Considered Options

- **起動したディレクトリを、既定で作業ディレクトリにする。** 普段のフォルダで使うのが最も手軽になる。ただし、`cd ~` で起動するだけで、ホームの中身が、登録したルームの誰の発言からでも、承認なしで読めて返せるようになる。ADR 0017 では、これを管理者の明示の指定に限っている。
- **`--workspace .` に、ハーネスの設定の読み込みも含める（「普段の環境で動かす」を 1 つのフラグにする）。** 手軽になる。ただし、ADR 0017 で 3 つを独立させた理由（組み合わせを選べること、メモリへの書き込みを別に選ばせること）がなくなる。
- **起動したディレクトリの設定ファイル（`.agent-chat-relay.toml` など）を読む。** フラグを毎回書かずに済む。ただし、エージェントや clone したリポジトリが、安全境界を緩める設定を置けてしまう。
- **秘密情報を dotenvx で暗号化し続ける。** 開発時と同じ形式で扱える。ただし、復号鍵が隣に置かれるので、リポジトリの外では、保護の強さは平文の 0600 と変わらない。暗号化した理由（public リポジトリに誤ってコミットしても漏れないこと）もなくなる。
- **秘密情報を OS のキーチェーンに置く。** 平文のファイルが残らない。ただし、`Bun.secrets` は実験段階で、画面のない Linux では使えないことが多い。macOS では、アクセスを確認する画面で、常駐する中継の起動が止まることがある。
- **XDG に従って、設定（`~/.config`）とデータ（`~/.local/share`、`~/.local/state`）に分ける。** Linux の慣習に沿う。ただし、置き場が散らばり、`RELAY_HOME` 1 つで中継を分けるという今の考え方（`docs/relay-setup.md` の「中継を分けて動かす」）と合わない。
- **コマンド名を `relay` にする。** 短い。ただし、一般的な名前なので、ほかのツールと衝突しやすい。

## Consequences

- 中継の本体を `scripts/relay.sh` を通さずに起動すると、データは `~/.agent-chat-relay/` に置かれます。
- 作業ディレクトリに置いた `.env` と `bunfig.toml` は、中継の本体にもアダプターにも読まれなくなります。ハーネス（Claude Code）自身が作業ディレクトリのファイルをどう読むかは、変わりません。
- 1 つの Bot（Webhook とポート）で同時に動かせる中継は 1 つです。プロジェクトごとに作業ディレクトリを変えるときは、中継を止めてから起動し直します。セッションの再開は作業ディレクトリに結びついているので、会話はディレクトリごとに分かれます。
- 中継を分けて動かす場合は、今までどおり `RELAY_HOME` とポートを分けます。
- npm のパッケージ名と、リリースの手順を保守する必要が生じます。
