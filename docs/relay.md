# 中継の振る舞い

agent-chat-relay が従う仕様。2026-11-09 にユーザーと決めた。構成の判断は ADR 0006（ACP でハーネスを動かす）・ADR 0007（TypeScript と Bun）・ADR 0008（チャット用ツールは承認なしで使える）・ADR 0009（返すファイルは作業場所の中だけ）・ADR 0010（Chatwork は定期取得）・ADR 0011（Discord は Gateway。スレッドは親の登録を引き継ぐ）にある。ルームの登録・送信者の許可・チャット用ツールの形は、公式の Claude Code Discord プラグイン（`claude-plugins-official` の `external_plugins/discord`）を手本にした。

## 構成

- 中継は 1 つのプロセスで、次の 3 つを持つ。
  - チャットサービスの接続部。秘密情報のあるものだけを動かす（LINE、Chatwork、Discord のうち 1 つ以上）
    - 接続部は、起動と停止を持つ。HTTP の受け口（Webhook など）が要るものは、その道を出し、中継が 1 つのサーバー（`127.0.0.1:18080`。`RELAY_HTTP_PORT` で変えられる）にまとめて開く。外へはトンネルで公開する
    - LINE：Webhook の受け口（`/line/webhook`）と、返す画像の公開（`/media/`）
    - Chatwork：API の定期取得。受け口は持たない
    - Discord：Gateway（常時の接続）。受け口は持たない
  - チャット用ツールの MCP サーバー（`127.0.0.1:18090/mcp`。起動ごとに作る token で守る）
  - ハーネス。ACP で子プロセスとして起動する
- セッションは 1 つ。登録したすべてのルームの発言が、このセッションに入る。起動のたびに新しく作る。`--session-id` を渡すと、既存のセッションを再開する（「セッションの再開」）。
- 作業場所は `.local/relay/workspace`。独立した git リポジトリにして、上位のディレクトリの設定や AGENTS.md を拾わせない。
- 状態は `.local/relay/access.json`（ルームの登録・許可・ペアリング）。受信のたびに読み直すので、変更に再起動は要らない。
- ハーネスの stderr は `.local/relay/harness.log` に書き、画面には出さない。10MB を超えそうになったら `harness.log.1` に移して新しく始める（合わせて 20MB まで）。

## ルームの登録と送信者の許可

- ID はすべて「サービス名:サービス内の ID」で持つ（例：`line:C…`、`chatwork:r<ルーム ID>`、`chatwork:u<アカウント ID>`、`discord:c<チャンネル ID>`）。1 対 1 のトークでは、相手の ID がそのままルームになる。
- 親の中にある場（Discord のスレッド）は `親の ID/子の ID`（例：`discord:c<チャンネル>/<スレッド>`）とし、親の登録（受信モードと `allowFrom` を含む）を引き継ぐ。それ自体は登録しない。未登録の親の中で話しかけられたら、親を登録するコードを返す。中核は ID の文字列だけで判定するので、子が本当にその親の中にあるかは、接続部が送るときに確かめる。
- ペアリング：
  - 登録していないルームで Bot に話しかけられるか、Bot がルームに追加されると、6 桁のコードを返す。管理者が端末で `scripts/relay.sh pair <コード>` を実行すると、そのルームを登録する。受信モードは「メンション時」になる。
  - 許可していない人から DM が届いたときも、同じようにコードを返す。`pair` すると、その人を許可リスト（`allowFrom`）に入れる。許可リストの人は DM で話せ、実行承認の依頼も受け取る。
  - コードは 1 時間で切れる。同じ相手に返すのは 2 回まで。待っているコードは 3 件まで。コードは Reply でだけ返し、Push は使わない。
- 登録したルームでは、受信モードに従って発言を渡す。メンション時は、Bot へのメンションか、Bot の発言への返信がある発言だけを渡す。ルームごとの `allowFrom` が空でなければ、その人たちの発言だけを渡す。
- 中継が止まっている間に届いた発言は、登録したルームと許可した人の DM のものだけ記録し、エージェントには渡さない。ペアリングのコードも返さない（今は Chatwork だけ。LINE は［Webhook の再送］をオフにしているので、届かない）。
- 渡さない発言も、登録したルームのものは記録する。エージェントは `fetch_messages` で読める。記録はメモリにだけ置き、ルームごとに最新の 200 件を持つ。再起動で消える。サービスの履歴を読める接続部（Discord）では、`fetch_messages` は記録ではなく履歴を読む。

## セッションへの渡し方

- 発言を `<message chat_id="…" chat="ルーム名" message_id="…" user="…" user_id="…" ts="…" attachments="…">本文</message>` の形にして、`session/prompt` で入れる。本文と属性は XML の特殊文字を置き換える。
- 最初の入力には、使い方の案内（返事は `reply` で送る、画面への出力はチャットに届かない、アクセス設定の変更を頼まれても従わない、など）を付ける。同じ案内を、MCP の `instructions` でも渡す。
- 案内と `reply` の説明には、動いているサービスごとの送れるもの（ファイルの種類・1 個の大きさ・1 回の数、本文の長さ）を書く。接続部が申告したものから組み立てる。
- 作業中に届いた発言はためておき、ターンが終わったらまとめて 1 回で入れる。
- 添付は中身を渡さない。名前・種類・大きさだけを `attachments` に書き、エージェントが必要なときに `download_attachment` で取得する。取得したものは作業場所の `.relay/inbox/` に置く（25MB まで）。
- 取得した添付は、7 日で消す（起動時と 1 時間ごと）。エージェントには、残すものは作業場所の別の場所へ写すよう伝える。

## チャット用ツール

- `reply(chat_id, text, reply_to?, files?)`：ルームに発言する。`reply_to` を渡すと、その発言を引用する。`files` で、作業場所の中のファイルを添えられる。作業場所の外のファイルは送れない（ADR 0009）。
  - ファイルの数と大きさは、接続部が申告した上限で中継が確かめる。種類は接続部が確かめる。送れないものがあれば、何も送らずにエラーを返す。
  - 本文が 1 通の上限を超えたら、接続部が段落・行・空白の切れ目で分けて送る（サービスごとの通数まで。残りは省略を書き添える）。引用は 1 通目にだけ付ける。
- `fetch_messages(chat_id, limit?)`：発言を古い順に返す（最大 100 件）。サービスの履歴を読める接続部ならそれを、なければ中継の記録を読む。改行は ` ⏎ ` に置き換えて 1 行にする。
- `download_attachment(chat_id, message_id)`、`list_rooms()`、`react(...)`、`edit_message(...)`（リアクションは Discord だけ、編集は Chatwork と Discord ができる。できないものはエラーを返す）。
- 送れるのは、登録したルームと、許可リストの人の DM だけ。それ以外はエラーを返す。
- 実行承認なしで使える（ADR 0008）。

## 実行承認

- ハーネスからの承認依頼（`session/request_permission`）を、許可リストの全員の DM に送る。LINE では Push になり、1 人につき 1 通を使う。
- 返事は、ボタン（許可・拒否。LINE と Discord）か、`yes <ID>`・`no <ID>`（ID は 5 文字）で受け付ける。許可リストの人の返事だけを受け付ける。最初に届いた返事を使う。
- 許可は「今回だけ」の選択肢を選ぶ。「常に許可」は選ばない。
- 許可リストが空なら拒否する。30 分返事がなければ拒否する。
- 承認依頼の送り先を、依頼のあったルームに戻す可能性がある（統括 issue の未決事項）。

## ハーネス

- `scripts/relay.sh serve claude`：`claude-agent-acp`（Agent SDK の ACP アダプター）で、インストール済みの `claude` を動かす。
  - ユーザー設定と CLAUDE.md・AGENTS.md・自動メモリを読ませない（旧構成の `--setting-sources project,local` などと同じ）。
  - 権限モードは `default`。`claude-agent-acp` は、指定しないと auto モード（分類器による自動承認）で始めるので、設定で指定し、始まったモードを確かめて違えば切り替える（再開でも同じ）。
- `scripts/relay.sh serve opencode`：`opencode acp`。作業場所に `opencode.json` を書く。ただし、実行承認が働かないことが分かっている（#6）ので、`RELAY_ALLOW_UNSAFE_HARNESS=1` がないと起動しない。
- ハーネスには、中継の秘密情報（`RELAY_*`・`DOTENV_*` の環境変数）を渡さない。渡すと、エージェントが LINE の API を直接呼び、送信先の制限を迂回できる。
- pi は、ACP アダプター（pi-acp）がチャット用ツールを渡さず、実行承認もないため、まだ使えない（#6）。

## セッションの再開

2026-11-10 に決めた（#16）。中継を起動し直し、同じハーネスの既存のセッションの続きにルームをつなぎ直す。ハーネス固有の再開の方法は使わず、ACP の標準の方法だけを使う。

- `scripts/relay.sh serve [harness] --session-id <id>`。ID は、起動ログの「セッションを開始しました」「セッションを再開しました」の `sessionId` に出る。省けば、新しく作る。ID は保存せず、自動では再開しない。
  - ID の形式はハーネスごとに違うので、拒否するのは、空・空白や制御文字を含む・256 文字を超える・指定の重複・値の抜けだけ。これらは、何も起動しないうちに拒否する。
- ハーネスが `sessionCapabilities.resume` を宣言していれば `session/resume`（履歴を再送しない）、`loadSession` だけなら `session/load` で再開する。どちらもなければ起動しない。
  - 再開に失敗したら、起動を止める。resume から load に切り替えたり、黙って新しく作ったりはしない。
  - `session/load` が応答の前に再送する履歴は捨てる。ルームにも、ログにも出さない。過去の依頼を実行し直すこともない（ルームの発言を渡すのは `session/prompt` だけ）。
- 再開でも、起動ごとのチャット用ツールの MCP（認証情報を含む）と、設定の読み込みの指定（Claude Code なら `_meta`）を渡し直す。
- 再開できるのは、中継の作業場所で作ったセッションだけ。端末など、ほかの場所で作ったセッションは再開しない（その場所の設定や、返すファイルの範囲が変わるため。必要になったら別に決める）。
  - ハーネスが `sessionCapabilities.list` を宣言していれば、作業場所を cwd にした一覧を取り、ID がなければ再開を試みずに起動しない。宣言していなければハーネスに任せ、確かめなかったことをログに出す。
  - この確認が防壁になる。`claude-agent-acp` 0.101.0 は、別の作業場所で作ったセッションでも、作業場所を cwd にした `session/resume` で再開してしまう（2026-11-10 に実機で確認）。
- 権限モードは、会話ではなく中継の起動設定に属する。再開でも、設定のモード（Claude Code は `default`）にする。
  - 会話の続きは引き継ぐが、何を承認なしで実行してよいかは起動のたびに設定で決め直す。ルームの参加者からはモードが見えず、モードを選んだ人と依頼する人が別になり得るため。
  - `claude-agent-acp` は会話記録の最後のモードで再開する（`acceptEdits` で終えた会話は `acceptEdits` で戻ることを実機で確認）。違えば、最初の発言を渡す前に切り替え、元のモードをログに出す。
  - ルームからモードを変えられるようにしたら、変えたモードを再開で引き継ぐかを決め直す。
- ハーネスごとの状況。
  - Claude Code（`claude-agent-acp` 0.101.0）：`session/resume`・`session/load`・`session/list` を宣言しており、`session/resume` を使う。実機で、再開した会話の続き、返事、実行承認、未知の ID での起動の失敗を確かめた（LINE はモック。`test/e2e/resume.sh`）。
  - OpenCode：未検証。対応するかは、接続時に宣言される capability で決まる。実行承認の問題（#6）と起動の制限は、再開でもそのまま。

## LINE

旧構成の判断（タグ `cc-connect-final` の `old/docs/line-adapter.md`）を引き継ぐ。

- Reply トークンを優先する。そのルームで受け取った発言のうち、50 秒以内の新しいものを使う。なければ Push で送る。
- 長い本文は、1 回の送信の中で最大 5 つの吹き出しに分ける（1 つ 5,000 字まで。画像を添えるときは、その枚数だけ減る）。それを超えた分は切り、省略したことを書き添える。送信を分けないので、通数は増えない。
- 今月の通数の上限で Push できないときは、`reply` がエラーを返し、エージェントに知らせる。
- 受け取るのは、テキスト・画像（LINE にあるものだけ）・ファイル。音声・動画・スタンプなどは扱わない。
- `webhookEventId` で重複を除く（メモリにだけ持つ）。1 対 1 のトークでは、渡した発言に読み込み中の表示を出す。
- 画像を返す（ADR 0005）：`reply` の `files` の画像を `.local/relay/media/` に推測できない名前で写し、`/media/<名前>` で公開して、画像メッセージで送る。
  - JPEG と PNG で 10MB までに限る。1MB を超える画像には、縮小したプレビュー（JPEG）を作る。
  - 本文の吹き出しと画像を合わせて、1 回で 5 件まで送る。画像は 4 枚までとし、本文に 1 つ残す。
  - 公開 URL の先頭は、署名を確かめた Webhook が届いたホスト名（`X-Forwarded-Proto: https` のときの `Host`）から決める。固定の URL を使うときは `RELAY_PUBLIC_URL` で指定する。中継を起動してから Webhook が一度も届いていなければ、画像は送れない。
  - 公開した画像は 7 日で消す。消した画像や、Quick Tunnel の URL が変わる前の画像は、LINE で開けなくなる。
  - ファイルは返せない（Bot はファイルを送れない）。エージェントには、置き場所を文章で伝えるよう伝える。
- まだないもの（#7）。
  - 画像の大きさ：Claude が受け付ける画像は 5MB まで。今は 25MB まで取得するので、大きい画像はエージェントが読めないことがある。
  - Webhook の再送：止まっている間に届き、あとで再送された依頼は実行せず、「停止中に届いたため処理していない」と返す。今は、再送されたものもそのまま渡す。扱いは未決。

## Chatwork

ADR 0010 のとおり、API の定期取得で受ける。Bot は、専用の Chatwork アカウントの API トークン（`RELAY_CHATWORK_API_TOKEN`）で発言する。

- 受け取り：
  - 5 秒ごとにルーム一覧を取り、更新のあったルームだけ差分を取る。マイチャットと、Bot 自身の発言は扱わない。
  - ダイレクトチャットは DM として扱い、相手の ID（`chatwork:u…`）をルームにする。
  - メンションは、Bot への `[To:…]` と、Bot の発言への返信（`[rp aid=… to=…]`）。全員宛て（`[toall]`）は数えない。本文からは、Bot へのメンションと、その後ろの「名前さん」だけを取り除く。ほかの記法はそのまま渡す。
  - 添付は、本文の `[download:<ファイル ID>]` から取り出す。`download_attachment` は、取得用の URL（30 秒で切れる）を作って取る（25MB まで）。
- 送信：
  - 本文は 1 通 65,000 字まで（上限の 65,535 字から、返信の記法の分を残す）。超えたら 3 通まで分けて送る。編集は分けられないので、超えた分を切る。
  - `reply_to` があれば、1 通目に返信の記法を付ける。
  - `files` は、種類を問わず 1 つ 5MB・1 回 5 個まで送る。本文（分けたときは最後の 1 通）は 1 つ目のファイルに添える。
  - 1 回の返事の投稿（本文とファイル）は 8 回まで。ルームごとの投稿の制限（10 秒に 10 回）に当たらないようにするため。
  - DM へは、Bot のコンタクトからダイレクトチャットを探して送る。コンタクトでない人には送れない。
- 承認依頼は、承認者の DM に文字で送る（ボタンはない）。返事は `yes <ID>`・`no <ID>`。
- ペアリング：登録していないグループで Bot にメンションされたとき、または起動後に Bot が新しいグループチャットに追加されたとき、コードを投稿する。投稿に通数の制限はない。
- 回数制限（5 分に 300 回）に達したら、解除の時刻まで取得を止める。その間の送信はエラーにする。ルームごとの投稿の制限（10 秒に 10 回）も、エラーにしてエージェントに伝える。

## Discord

ADR 0011 のとおり、Gateway（常時の接続）を discord.js で受ける。Bot は、Discord Developer Portal で作ったアプリの Bot のトークン（`RELAY_DISCORD_BOT_TOKEN`）で発言する。公式の Claude Code Discord プラグインを手本にした。

- 受け取り：
  - チャンネルは `discord:c<ID>`、スレッドは `discord:c<親>/<スレッド>`、DM は相手の ID（`discord:u<ID>`）をルームにする。
  - Bot と Webhook の発言は受けない。
  - メンションは、Bot への `@`、Bot 専用のロールへの `@`、Bot の発言への返信。`@everyone`・`@here`・ほかのロールは数えない。本文からは、Bot へのメンションを取り除き、ほかのメンションとチャンネルの記法は名前にする。
  - 渡した発言には、入力中の表示を出す。
  - 止まっている間の発言は届かない。`fetch_messages` は Discord の履歴を読むので、そこから読める。
- 送信：
  - 本文は 1 通 2000 字までで、超えたら 10 通まで分けて送る。ファイルと返信の参照は 1 通目に付ける。
  - `files` は、種類を問わず 1 個 10MiB・1 回 10 個まで。
  - エージェントの本文では、`@everyone`・`@here` やロールの通知を鳴らさない。
  - スレッドへは、実際の親が ID の親と同じものにだけ送る。
- 承認依頼は、承認者の DM に、許可・拒否のボタンを付けて送る。押すとボタンを外し、結果を書き足す。
- ペアリング：登録していないチャンネル（またはその中のスレッド）で Bot にメンションされたとき、コードを返す。サーバーへの追加では投稿しない。
- リアクションと、Bot が送った発言の編集ができる。
