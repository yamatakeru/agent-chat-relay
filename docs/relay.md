# 中継の仕様

agent-chat-relay の仕様です。2026-11-09 にユーザーと決めました。構成に関わる判断は、次の ADR にあります。

| ADR | 内容 |
|---|---|
| [0006](adr/0006-own-core-drives-any-harness-over-acp.md) | ACP でハーネスを動かす |
| [0007](adr/0007-typescript-on-bun.md) | TypeScript と Bun で実装する |
| [0008](adr/0008-chat-tools-without-approval.md) | チャット用ツールは実行承認なしで使える |
| [0009](adr/0009-returned-files-from-workspace-without-approval.md) | 返せるファイルは作業ディレクトリの中のものに限る |
| [0010](adr/0010-chatwork-by-polling.md) | Chatwork は API のポーリングで受信する |
| [0011](adr/0011-discord-via-gateway.md) | Discord は Gateway で受信し、スレッドは親チャンネルの登録を引き継ぐ |
| [0012](adr/0012-acknowledge-receipt-per-service.md) | 受け取りの合図は、いつ出すかを中核が、どう出すかをコネクターが決める |
| [0013](adr/0013-describe-supported-operations-in-tools.md) | サービスによって使えない操作は、ツールの説明に書き、使えるサービスがなければツールを出さない |
| [0014](adr/0014-batch-permission-requests.md) | 同時に届いた実行承認の依頼は、1 通の承認依頼の束にまとめる |
| [0015](adr/0015-allow-always-by-approver.md) | 承認者は、ハーネスが示した「常に許可」を選べる |

ルームの登録、送信者の許可、チャット用ツールの設計は、公式の Claude Code Discord プラグイン（`claude-plugins-official` の `external_plugins/discord`）を参考にしています。

## 構成

- 中継は 1 つのプロセスで、次の 3 つで構成されます。
  - **チャットサービスのコネクター**：秘密情報が設定されているものだけが起動します（LINE・Chatwork・Discord のうち 1 つ以上）。
    - 各コネクターは起動と停止の処理を持ちます。Webhook などの HTTP エンドポイントが必要なコネクターはそのパスを登録し、中継がそれらを 1 つの HTTP サーバー（`127.0.0.1:18080`。`RELAY_HTTP_PORT` で変更可）にまとめて公開します。外部からはトンネル経由でアクセスします。
    - LINE：Webhook のエンドポイント（`/line/webhook`）と、返信する画像の配信（`/media/`）
    - Chatwork：API のポーリング。エンドポイントは持ちません。
    - Discord：Gateway（常時接続）。エンドポイントは持ちません。
  - **チャット用ツールの MCP サーバー**：`127.0.0.1:18090/mcp`。起動のたびに生成するトークンで保護します。
  - **ハーネス**：ACP で子プロセスとして起動します。
- セッションは 1 つだけで、登録したすべてのルームの発言がこのセッションに入ります。セッションは起動のたびに新しく作ります。`--session-id` を指定すると、既存のセッションを再開します（「[セッションの再開](#セッションの再開)」）。
- 作業ディレクトリは `.local/relay/workspace` です。独立した git リポジトリにして、上位ディレクトリの設定や AGENTS.md を読み込ませないようにしています。`git init` に失敗した場合（git がない場合を含む）は起動しません。
- 状態は `.local/relay/access.json` に保存します（ルームの登録、送信者の許可、ペアリング）。受信のたびに読み直すので、変更しても再起動は不要です。
- ハーネスの標準エラー出力は `.local/relay/harness.log` に書き込み、画面には表示しません。10MB を超えそうになると `harness.log.1` に移して新しいファイルに切り替えます（合計で最大 20MB）。

## ルームの登録と送信者の許可

- ID はすべて「サービス名:サービス内の ID」の形式で扱います（例：`line:C…`、`chatwork:r<ルーム ID>`、`chatwork:u<アカウント ID>`、`discord:c<チャンネル ID>`）。1 対 1 のトークでは、相手の ID をそのままルームの ID にします。
- 親の中にある場（Discord のスレッド）は `親の ID/子の ID` の形式（例：`discord:c<チャンネル>/<スレッド>`）で表し、親の登録（受信モードと `allowFrom` を含む）を引き継ぎます。スレッド自体は登録しません。未登録の親の中で話しかけられた場合は、親を登録するためのコードを返します。中核は ID の文字列だけで判定するため、子が実際にその親に属しているかどうかは、コネクターが送信時に確認します。
- ペアリング
  - 登録していないルームで Bot に話しかけられるか、Bot がルームに追加されると、6 桁のコードを返します。管理者が端末で `scripts/relay.sh pair <コード>` を実行すると、そのルームが登録されます。受信モードは「メンション時」になります。
  - 許可していない人から DM が届いた場合も、同じようにコードを返します。`pair` を実行すると、その人が許可リスト（`allowFrom`）に追加されます。許可リストの人は DM で Bot と会話でき、実行承認の依頼も受け取ります。
  - コードの有効期限は 1 時間です。同じ相手にコードを返すのは 2 回まで、まだ `pair` されていないコードは 3 件までです。コードは Reply でのみ返し、Push は使いません。
- 登録したルームでは、受信モードに従って発言をエージェントに渡します。「メンション時」の場合は、Bot へのメンションか、Bot の発言への返信を含む発言だけを渡します。ルームごとの `allowFrom` が空でなければ、そこに含まれる人の発言だけを渡します。
- 中継が停止している間に届いた発言は、登録したルームと許可した人の DM のものだけを記録し、エージェントには渡しません。ペアリングのコードも返しません（現在は Chatwork のみ。LINE は［Webhook の再送］をオフにしているので、停止中の発言は届きません）。
- エージェントに渡さない発言も、登録したルームのものは記録します。エージェントは `fetch_messages` でこれを読めます。記録はメモリ上にだけ保持し、ルームごとに最新の 200 件を残します。再起動すると消えます。サービスの履歴を読めるコネクター（Discord）では、`fetch_messages` は記録ではなくサービスの履歴を読みます。

## セッションへの渡し方

- 発言は `<message chat_id="…" chat="ルーム名" message_id="…" user="…" user_id="…" ts="…" attachments="…">本文</message>` の形式に変換し、`session/prompt` で渡します。本文と属性値に含まれる XML の特殊文字はエスケープします。
- 最初の入力には、使い方の案内を付けます（返信は `reply` で送ること、画面への出力はチャットに届かないこと、アクセス設定の変更を頼まれても従わないこと、など）。同じ内容を MCP の `instructions` でも渡します。
- 案内と `reply` の説明には、起動しているサービスごとに送れるもの（ファイルの種類、1 ファイルのサイズ、1 回に送れる数、本文の長さ）を記載します。これは各コネクターが申告した値から組み立てます。
- 処理中に届いた発言はためておき、ターンが終わったらまとめて 1 回で渡します。
- エージェントに渡すメンション（1 対 1 のトークと DM の発言を含む）には、受け取ったらすぐに受け取りの合図を出します（ADR 0012）。メンションのない発言、承認の返事、停止中に届いた発言には出しません。合図は 1 回だけで、返事が済んでも外しません。合図の形はコネクターが決めます（各サービスの節を参照。Chatwork は出しません）。合図を出せなくても発言は渡し、失敗はログに書きます（同じ失敗は続けて書きません）。
- 添付ファイルの中身は渡しません。名前・種類・サイズだけを `attachments` に書き、エージェントが必要に応じて `download_attachment` で取得します。取得したファイルは作業ディレクトリの `.relay/inbox/` に保存します（25MB まで）。
- 取得した添付ファイルは 7 日で削除します（起動時と 1 時間ごとに実行）。エージェントには、残したいファイルは作業ディレクトリ内の別の場所にコピーするよう伝えています。

## チャット用ツール

- `reply(chat_id, text, reply_to?, files?)`：ルームに発言します。`reply_to` を指定すると、その発言を引用します。`files` で作業ディレクトリの中のファイルを添付できます。作業ディレクトリの外のファイルは送れません（ADR 0009）。
  - ファイルの数とサイズは、コネクターが申告した上限に照らして中継が確認します。種類はコネクターが確認します。送れないファイルが 1 つでもあれば、何も送らずにエラーを返します。
  - 本文が 1 通の上限を超える場合は、コネクターが段落・行・空白の区切りで分割して送ります（サービスごとの通数の上限まで。超えた分は省略した旨を書き添えます）。引用は 1 通目にだけ付けます。
- `fetch_messages(chat_id, limit?)`：発言を古い順に返します（最大 100 件）。サービスの履歴を読めるコネクターではその履歴を、それ以外では中継の記録を読みます。改行は ` ⏎ ` に置き換えて 1 行にします。
- `download_attachment(chat_id, message_id)`、`list_rooms()`、`react(...)`、`edit_message(...)`：リアクションは Discord のみ、編集は Chatwork と Discord で使えます（ADR 0013）。
  - サービスによって使えない操作は、つながっているコネクターから、ツールの説明に使えるサービスを書きます。使えるサービスが 1 つもなければ、そのツールを出しません（LINE だけの構成では、`react` と `edit_message` が出ません）。
  - 使えないサービスで呼ばれたら、使えるサービスと代わりの手段を書いたエラーを返します。
- 送信できるのは、登録したルームと、許可リストの人の DM だけです。それ以外への送信はエラーになります。
- チャット用ツールは実行承認なしで使えます（ADR 0008）。

## 実行承認

- ハーネスからの承認依頼（`session/request_permission`）は、許可リストの全員の DM に送ります。LINE では Push になるため、1 人につき 1 通を消費します。
- 同時に届いた依頼は、承認依頼の束として 1 通にまとめて送ります（ADR 0014）。最後の依頼から 1 秒、次の依頼が来なければ送ります。依頼が続いても、最初の依頼から 3 秒で送ります。1 つの束には 5 つまで入れます。
  - Claude Code では、並列に実行できるツール（読み取り専用の MCP ツールなど）を並列に呼ぶと、依頼が同時に届きます。Bash の書き込みなどは、前の依頼に答えるまで次の依頼が届きません。
- 返事は、ボタン（許可・拒否。LINE と Discord）か、`yes <ID>`・`no <ID>`（ID は 5 文字）で受け付けます。受け付けるのは許可リストの人の返事だけで、最初に届いた返事を採用します。
  - ボタンと束の ID は、その束に残っているすべての依頼に答えます。束の中の依頼にはそれぞれ ID があり、1 つずつ答えることもできます。
  - 答えを受け付けたあと、答えていない束が残っていれば、いちばん古い束を、残りの件数を添えてその人に送り直します。LINE のボタン（quickReply）は、あとから発言が届くと消えるためです。LINE では、この送り直しも Push になります。
- 許可は、ふだんは「今回だけ許可」の選択肢を選びます。ハーネスが「常に許可」（ACP の `allow_always`）を示した依頼では、承認者が「常に許可」も選べます（ADR 0015）。
  - ボタン（常に許可）か、`always <ID>` で答えます。文面には、ハーネスが示した範囲（選択肢の名前）をそのまま書きます。束全体へのボタンは、束のすべての依頼に「常に許可」が示されたときだけ付けます。示されていない依頼に `always` で答えると、今回だけの許可として扱います。
  - モードの切り替え（ACP の `kind` が `switch_mode`）とファイルの編集（`edit`）の依頼には、「常に許可」を出しません。Claude Code では、計画の承認から auto や bypassPermissions への切り替え、セッションのあいだの編集の自動許可になるためです。
  - 記憶するのはハーネスです。Claude Code では、MCP ツールの許可は作業ディレクトリの `.claude/settings.local.json` に書かれ、中継を再起動しても続きます。取り消すには、管理者が端末でこのファイルを直します。チャットからは取り消せません。
  - 作業ディレクトリの `.claude/` と `.mcp.json` への書き込みの依頼は、許可しないでください。ハーネスの許可そのものを書き換えられます。
- 許可リストが空の場合は拒否します。30 分以内に返事がなければ拒否します。
- 承認依頼の送り先を、依頼のあったルームに変更する可能性があります（統括 issue の未決事項）。

## ハーネス

- `scripts/relay.sh serve claude`：`claude-agent-acp`（Agent SDK の ACP アダプター）経由で、インストール済みの `claude` を起動します。
  - ユーザー設定、CLAUDE.md・AGENTS.md、自動メモリは読み込ませません（旧構成の `--setting-sources project,local` などと同等）。
  - 権限モードは `default` です。`claude-agent-acp` は指定がないと auto モード（分類器による自動承認）で始まるため、設定でモードを指定したうえで、開始後のモードを確認し、異なっていれば切り替えます（再開時も同様）。
- `scripts/relay.sh serve opencode`：`opencode acp` を起動し、作業ディレクトリに `opencode.json` を書き込みます。ただし、実行承認が働かないことが分かっているため（#6）、`RELAY_ALLOW_UNSAFE_HARNESS=1` を指定しない限り起動しません。
- ハーネスには、中継の秘密情報（環境変数 `RELAY_*`・`DOTENV_*`）を渡しません。渡すと、エージェントが LINE の API を直接呼び出し、送信先の制限を回避できてしまうためです。
- pi は、ACP アダプター（pi-acp）がチャット用ツールを渡さず、実行承認の仕組みもないため、まだ使えません（#6）。

## セッションの再開

2026-11-10 に決めました（#16）。中継を起動し直したときに、同じハーネスの既存のセッションの続きにルームをつなぎ直す機能です。ハーネス固有の再開方法は使わず、ACP の標準の方法だけを使います。

- 起動方法は `scripts/relay.sh serve [harness] --session-id <id>` です。ID は、起動ログの「セッションを開始しました」または「セッションを再開しました」の `sessionId` に表示されます。省略すると新しいセッションを作ります。ID は保存せず、自動での再開もしません。
  - ID の形式はハーネスごとに異なるため、形式は制限しません。拒否するのは、空の値、空白や制御文字を含む値、256 文字を超える値、オプションの重複、値の指定漏れだけです。これらは、何も起動しないうちに拒否します。
- ハーネスが `sessionCapabilities.resume` を宣言していれば `session/resume`（履歴を再送しない）で、`loadSession` だけを宣言していれば `session/load` で再開します。どちらもなければ起動しません。
  - 再開に失敗した場合は起動を中止します。resume から load への切り替えや、新しいセッションの自動作成はしません。
  - `session/load` が応答の前に再送する履歴は破棄します。ルームにもログにも出しません。過去の依頼を再実行することもありません（ルームの発言を渡すのは `session/prompt` だけです）。
- 再開時も、起動ごとに作るチャット用ツールの MCP 設定（認証情報を含む）と、設定の読み込みに関する指定（Claude Code では `_meta`）を渡し直します。
- 再開できるのは、中継の作業ディレクトリで作ったセッションだけです。端末など別の場所で作ったセッションは再開しません（その場所の設定や、返せるファイルの範囲が変わってしまうため。必要になったら別途決めます）。
  - ハーネスが `sessionCapabilities.list` を宣言していれば、作業ディレクトリを cwd とするセッションの一覧を取得し、指定した ID が含まれていなければ、再開を試みずに起動を中止します。宣言していない場合はハーネスに任せ、確認しなかったことをログに出力します。
  - この確認が安全策になります。`claude-agent-acp` 0.101.0 は、別の作業ディレクトリで作ったセッションでも、作業ディレクトリを cwd とした `session/resume` で再開してしまいます（2026-11-10 に実機で確認）。
- 権限モードは、会話ではなく中継の起動設定で決まります。再開時も、設定どおりのモード（Claude Code では `default`）にします。
  - 会話の続きは引き継ぎますが、何を承認なしで実行してよいかは、起動のたびに設定で決め直します。ルームの参加者にはモードが見えず、モードを選んだ人と依頼する人が別人である可能性もあるためです。
  - `claude-agent-acp` は、会話記録の最後のモードで再開します（`acceptEdits` で終えた会話は `acceptEdits` で再開されることを実機で確認）。モードが異なる場合は、最初の発言を渡す前に切り替え、元のモードをログに出力します。
  - ルームからモードを変更できるようにする場合は、変更したモードを再開時に引き継ぐかどうかを改めて決めます。
- ハーネスごとの対応状況
  - Claude Code（`claude-agent-acp` 0.101.0）：`session/resume`・`session/load`・`session/list` を宣言しており、`session/resume` を使います。実機で、再開後の会話の継続、返信、実行承認、存在しない ID での起動の失敗を確認しました（LINE はモック。`test/e2e/resume.sh`）。
  - OpenCode：未検証です。対応するかどうかは、接続時に宣言される capability で決まります。実行承認の問題（#6）と起動の制限は、再開時もそのまま適用されます。

## LINE

旧構成での判断（タグ `cc-connect-final` の `old/docs/line-adapter.md`）を引き継いでいます。

- Reply トークンを優先して使います。そのルームで受け取った発言のうち、50 秒以内の新しいもののトークンを使い、なければ Push で送ります。
- 長い本文は、1 回の送信の中で最大 5 つの吹き出しに分けます（1 つあたり 5,000 字まで。画像を添付する場合は、その枚数分だけ減ります）。それを超えた部分は切り捨て、省略した旨を書き添えます。送信自体は分割しないので、通数は増えません。
- 月間の通数の上限に達して Push できない場合は、`reply` がエラーを返し、エージェントに伝えます。
- 受信するのは、テキスト、画像・動画・音声（LINE 上にあるものだけ）、ファイル、位置情報、スタンプです。それ以外の種類は扱いません。
  - 画像・動画・音声・ファイルは添付として渡します。動画と音声は、LINE 側の変換が済むまで取得できないので、取得の前に変換の状態（`/content/transcoding`）を確かめます。
  - 位置情報は、名前・住所・緯度と経度を本文にします。スタンプは、メッセージスタンプに入力した文字か、キーワード（先頭の 5 つ）を本文にします。
  - LINE でメンションを付けられるのはテキストだけなので、グループでは、テキスト以外の発言は記録するだけです（Bot の発言へのスタンプの返信は、メンションとして扱います）。
- `webhookEventId` で重複を除去します（メモリ上にだけ保持）。
- 受け取りの合図（ADR 0012）：発言に付いてくる既読トークン（`markAsReadToken`）で既読を付けます。1 対 1 のトークでは、ローディング表示（60 秒）も出します。
  - 既読を API で付けるには、OAM の［チャット］をオンにします。オフのままだと、LINE が受けた時点で既読が自動で付き、API では付けられません。
  - 既読は、そのトークの、それより前の発言にもまとめて付きます。合図を出さない発言（メンションのない発言、中継が止まっていたあいだの発言）も、あとのメンションで既読になります。
  - 実サービスで、1 対 1 のトークとグループのどちらの発言にも既読トークンが付くことを確かめました（2026-11-15）。メンションにはすぐに既読が付き、1 対 1 のトークではローディングも出ます。メンションのない発言には既読が付かず、あとのメンションでまとめて付きます。
- 画像の返信（ADR 0005）：`reply` の `files` に含まれる画像を、推測できない名前で `.local/relay/media/` にコピーし、`/media/<名前>` で公開して、画像メッセージとして送ります。
  - 対応するのは JPEG と PNG で、10MB までです。1MB を超える画像には、縮小したプレビュー画像（JPEG）を作ります。
  - 本文の吹き出しと画像を合わせて、1 回に 5 件まで送ります。画像は 4 枚までとし、本文用に 1 枠を残します。
  - 公開 URL のホスト部分は、署名を検証した Webhook が届いたホスト名（`X-Forwarded-Proto: https` のときの `Host`）から決めます。固定の URL を使う場合は `RELAY_PUBLIC_URL` で指定します。中継の起動後に Webhook が一度も届いていなければ、画像は送れません。
  - 公開した画像は 7 日で削除します。削除した画像や、Quick Tunnel の URL が変わる前に送った画像は、LINE で開けなくなります。
  - ファイルは返せません（Bot からはファイルを送れないため）。エージェントには、保存場所を文章で伝えるよう指示しています。

## Chatwork

ADR 0010 のとおり、API のポーリングで受信します。Bot は、専用の Chatwork アカウントの API トークン（`RELAY_CHATWORK_API_TOKEN`）で発言します。

- 受信
  - 5 秒ごとにルーム一覧を取得し、更新のあったルームだけ差分を取得します。マイチャットと、Bot 自身の発言は扱いません。
  - ダイレクトチャットは DM として扱い、相手の ID（`chatwork:u…`）をルームの ID にします。
  - メンションとして扱うのは、Bot 宛ての `[To:…]` と、Bot の発言への返信（`[rp aid=… to=…]`）です。全員宛て（`[toall]`）は含みません。本文からは、Bot へのメンションと、その後ろの「名前さん」だけを取り除き、ほかの記法はそのまま渡します。
  - 添付ファイルは、本文中の `[download:<ファイル ID>]` から取り出します。`download_attachment` は、取得用の URL（有効期限 30 秒）を発行して取得します（25MB まで）。
- 送信
  - 本文は 1 通 65,000 字までです（上限の 65,535 字から、返信の記法の分を差し引いています）。超える場合は 3 通まで分割して送ります。編集は分割できないため、超えた部分を切り捨てます。
  - `reply_to` を指定した場合は、1 通目に返信の記法を付けます。
  - `files` は、種類を問わず 1 ファイル 5MB、1 回 5 個まで送れます。本文（分割した場合は最後の 1 通）は、1 つ目のファイルに添えます。
  - 1 回の返信での投稿（本文とファイル）は 8 回までです。ルームごとの投稿の制限（10 秒に 10 回）に引っかからないようにするためです。
  - DM は、Bot のコンタクトからダイレクトチャットを探して送ります。コンタクトでない人には送れません。
- 承認依頼は、承認者の DM にテキストで送ります（ボタンはありません）。返事は `yes <ID>`・`no <ID>`（「常に許可」が示された依頼では `always <ID>` も）で受け付けます。
- ペアリング：登録していないグループで Bot がメンションされたとき、または起動後に Bot が新しいグループチャットに追加されたときに、コードを投稿します。LINE と違い、投稿の通数に制限はありません。
- API の回数制限（5 分に 300 回）に達した場合は、制限が解除される時刻まで取得を止めます。その間の送信はエラーにします。ルームごとの投稿の制限（10 秒に 10 回）に達した場合も、エラーとしてエージェントに伝えます。

## Discord

ADR 0011 のとおり、Gateway（常時接続）を discord.js で受信します。Bot は、Discord Developer Portal で作成したアプリの Bot トークン（`RELAY_DISCORD_BOT_TOKEN`）で発言します。公式の Claude Code Discord プラグインを参考にしています。

- 受信
  - チャンネルは `discord:c<ID>`、スレッドは `discord:c<親>/<スレッド>`、DM は相手の ID（`discord:u<ID>`）をルームの ID にします。
  - Bot と Webhook による発言は受信しません。
  - メンションとして扱うのは、Bot への `@`、Bot 専用ロールへの `@`、Bot の発言への返信です。`@everyone`・`@here`・ほかのロールへのメンションは含みません。本文からは Bot へのメンションを取り除き、ほかのメンションとチャンネルの記法は名前に置き換えます。
  - 受け取りの合図（ADR 0012）として、発言に 👀 のリアクションを付け、入力中の表示を出します。リアクションには、チャンネルで Add Reactions の権限が必要です。
  - 停止中の発言は届きませんが、`fetch_messages` は Discord の履歴を読むので、そこから参照できます。
- 送信
  - 本文は 1 通 2,000 字までで、超える場合は 10 通まで分割して送ります。ファイルと返信の参照は 1 通目に付けます。
  - `files` は、種類を問わず 1 ファイル 10MiB、1 回 10 個までです。
  - エージェントが書いた本文では、`@everyone`・`@here` やロールへの通知が飛ばないようにしています。
  - スレッドへの送信は、実際の親チャンネルが ID に含まれる親と一致する場合だけ行います。
- 承認依頼は、承認者の DM に、許可・拒否のボタンを付けて送ります。ボタンが押されるとボタンを外し、結果を追記します。
- ペアリング：登録していないチャンネル（またはその中のスレッド）で Bot がメンションされたときに、コードを返します。サーバーに追加されたときには投稿しません。
- リアクションと、Bot が送った発言の編集ができます。
