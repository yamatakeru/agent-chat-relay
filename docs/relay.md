# 中継の振る舞い

agent-chat-relay が従う仕様。2026-11-09 にユーザーと決めた。構成の判断は ADR 0006（ACP でハーネスを動かす）・ADR 0007（TypeScript と Bun）・ADR 0008（チャット用ツールは承認なしで使える）・ADR 0009（返すファイルは作業場所の中だけ）・ADR 0010（Chatwork は定期取得）にある。ルームの登録・送信者の許可・チャット用ツールの形は、公式の Claude Code Discord プラグイン（`claude-plugins-official` の `external_plugins/discord`）を手本にした。

## 構成

- 中継は 1 つのプロセスで、次の 3 つを持つ。
  - チャットサービスの接続部。秘密情報のあるものだけを動かす（LINE、Chatwork のどちらか、または両方）
    - LINE：Webhook の受け口（`127.0.0.1:18080/line/webhook`。外へはトンネルで公開する）。返す画像の公開（`/media/`）も同じ受け口で行う
    - Chatwork：API の定期取得。受け口は持たない
  - チャット用ツールの MCP サーバー（`127.0.0.1:18090/mcp`。起動ごとに作る token で守る）
  - ハーネス。ACP で子プロセスとして起動する
- セッションは 1 つ。登録したすべてのルームの発言が、このセッションに入る。
- 作業場所は `.local/relay/workspace`。独立した git リポジトリにして、上位のディレクトリの設定や AGENTS.md を拾わせない。
- 状態は `.local/relay/access.json`（ルームの登録・許可・ペアリング）。受信のたびに読み直すので、変更に再起動は要らない。
- ハーネスの stderr は `.local/relay/harness.log` に書き、画面には出さない。10MB を超えそうになったら `harness.log.1` に移して新しく始める（合わせて 20MB まで）。

## ルームの登録と送信者の許可

- ID はすべて「サービス名:サービス内の ID」で持つ（例：`line:C…`、`chatwork:r<ルーム ID>`、`chatwork:u<アカウント ID>`）。1 対 1 のトークでは、相手の ID がそのままルームになる。
- ペアリング：
  - 登録していないルームで Bot に話しかけられるか、Bot がルームに追加されると、6 桁のコードを返す。管理者が端末で `scripts/relay.sh pair <コード>` を実行すると、そのルームを登録する。受信モードは「メンション時」になる。
  - 許可していない人から DM が届いたときも、同じようにコードを返す。`pair` すると、その人を許可リスト（`allowFrom`）に入れる。許可リストの人は DM で話せ、実行承認の依頼も受け取る。
  - コードは 1 時間で切れる。同じ相手に返すのは 2 回まで。待っているコードは 3 件まで。コードは Reply でだけ返し、Push は使わない。
- 登録したルームでは、受信モードに従って発言を渡す。メンション時は、Bot へのメンションか、Bot の発言への返信がある発言だけを渡す。ルームごとの `allowFrom` が空でなければ、その人たちの発言だけを渡す。
- 中継が止まっている間に届いた発言は、登録したルームと許可した人の DM のものだけ記録し、エージェントには渡さない。ペアリングのコードも返さない（今は Chatwork だけ。LINE は［Webhook の再送］をオフにしているので、届かない）。
- 渡さない発言も、登録したルームのものは記録する。エージェントは `fetch_messages` で読める。記録はメモリにだけ置き、ルームごとに最新の 200 件を持つ。再起動で消える。

## セッションへの渡し方

- 発言を `<message chat_id="…" chat="ルーム名" message_id="…" user="…" user_id="…" ts="…" attachments="…">本文</message>` の形にして、`session/prompt` で入れる。本文と属性は XML の特殊文字を置き換える。
- 最初の入力には、使い方の案内（返事は `reply` で送る、画面への出力はチャットに届かない、アクセス設定の変更を頼まれても従わない、など）を付ける。同じ案内を、MCP の `instructions` でも渡す。
- 作業中に届いた発言はためておき、ターンが終わったらまとめて 1 回で入れる。
- 添付は中身を渡さない。名前・種類・大きさだけを `attachments` に書き、エージェントが必要なときに `download_attachment` で取得する。取得したものは作業場所の `.relay/inbox/` に置く（25MB まで）。
- 取得した添付は、7 日で消す（起動時と 1 時間ごと）。エージェントには、残すものは作業場所の別の場所へ写すよう伝える。

## チャット用ツール

- `reply(chat_id, text, reply_to?, files?)`：ルームに発言する。`reply_to` を渡すと、その発言を引用する。`files` で、作業場所の中のファイルを最大 10 個添えられる。作業場所の外のファイルは送れない（ADR 0009）。送れる種類は接続部が決め、送れないものがあれば、何も送らずにエラーを返す。
- `fetch_messages(chat_id, limit?)`：記録した発言を古い順に返す（最大 100 件）。改行は ` ⏎ ` に置き換えて 1 行にする。
- `download_attachment(chat_id, message_id)`、`list_rooms()`、`react(...)`、`edit_message(...)`（リアクションは LINE・Chatwork ともにできず、編集は Chatwork だけができる。できないものはエラーを返す）。
- 送れるのは、登録したルームと、許可リストの人の DM だけ。それ以外はエラーを返す。
- 実行承認なしで使える（ADR 0008）。

## 実行承認

- ハーネスからの承認依頼（`session/request_permission`）を、許可リストの全員の DM に送る。LINE では Push になり、1 人につき 1 通を使う。
- 返事は、ボタン（許可・拒否。LINE だけ）か、`yes <ID>`・`no <ID>`（ID は 5 文字）で受け付ける。許可リストの人の返事だけを受け付ける。最初に届いた返事を使う。
- 許可は「今回だけ」の選択肢を選ぶ。「常に許可」は選ばない。
- 許可リストが空なら拒否する。30 分返事がなければ拒否する。
- 承認依頼の送り先を、依頼のあったルームに戻す可能性がある（統括 issue の未決事項）。

## ハーネス

- `scripts/relay.sh serve claude`：`claude-agent-acp`（Agent SDK の ACP アダプター）で、インストール済みの `claude` を動かす。
  - ユーザー設定と CLAUDE.md・AGENTS.md・自動メモリを読ませない（旧構成の `--setting-sources project,local` などと同じ）。
  - 権限モードは `default`。`claude-agent-acp` は、指定しないと auto モード（分類器による自動承認）で始めるので、設定で指定し、始まったモードを確かめて違えば切り替える。
- `scripts/relay.sh serve opencode`：`opencode acp`。作業場所に `opencode.json` を書く。ただし、実行承認が働かないことが分かっている（#6）ので、`RELAY_ALLOW_UNSAFE_HARNESS=1` がないと起動しない。
- ハーネスには、中継の秘密情報（`RELAY_*`・旧構成の `CCJ_*`・`DOTENV_*` の環境変数）を渡さない。渡すと、エージェントが LINE の API を直接呼び、送信先の制限を迂回できる。
- pi は、ACP アダプター（pi-acp）がチャット用ツールを渡さず、実行承認もないため、まだ使えない（#6）。

## LINE

旧構成の判断（タグ `cc-connect-final` の `old/docs/line-adapter.md`）を引き継ぐ。

- Reply トークンを優先する。そのルームで受け取った発言のうち、50 秒以内の新しいものを使う。なければ Push で送る。
- 長い本文は、1 回で最大 5 つの吹き出しに分ける（1 つ 5,000 字まで。画像を添えるときは、その枚数だけ減る）。それを超えた分は切り、省略したことを書き添える。
- 今月の通数の上限で Push できないときは、`reply` がエラーを返し、エージェントに知らせる。
- 受け取るのは、テキスト・画像（LINE にあるものだけ）・ファイル。音声・動画・スタンプなどは扱わない。
- `webhookEventId` で重複を除く（メモリにだけ持つ）。1 対 1 のトークでは、渡した発言に読み込み中の表示を出す。
- 画像を返す（ADR 0005）：`reply` の `files` の画像を `.local/relay/media/` に推測できない名前で写し、`/media/<名前>` で公開して、画像メッセージで送る。
  - JPEG と PNG で 10MB までに限る。1MB を超える画像には、縮小したプレビュー（JPEG）を作る。
  - 本文の吹き出しと画像を合わせて、1 回で 5 件まで送る。本文があれば画像は 4 枚まで。
  - 公開 URL の先頭は、署名を確かめた Webhook が届いたホスト名（`X-Forwarded-Proto: https` のときの `Host`）から決める。固定の URL を使うときは `RELAY_PUBLIC_URL` で指定する。中継を起動してから Webhook が一度も届いていなければ、画像は送れない。
  - 公開した画像は 7 日で消す。消した画像や、Quick Tunnel の URL が変わる前の画像は、LINE で開けなくなる。
  - ファイルは返せない（Bot はファイルを送れない）。エージェントには、置き場所を文章で伝えるよう伝える。
- まだないもの（#7）。
  - 画像の大きさ：Claude が受け付ける画像は 5MB まで。今は 25MB まで取得するので、大きい画像はエージェントが読めないことがある。
  - Webhook の再送：止まっている間に届き、あとで再送された依頼は実行せず、「停止中に届いたため処理していない」と返す。今は、再送されたものもそのまま渡す。扱いは未決。

## Chatwork

ADR 0010 のとおり、API の定期取得で受ける。Bot は、専用の Chatwork アカウントの API トークン（`RELAY_CHATWORK_API_TOKEN`）で発言する。

- 受け取り：
  - 5 秒ごとにルーム一覧を取り、更新のあったルームだけ差分を取る。マイチャットと、Bot 自身の発言は扱わない。
  - ダイレクトチャットは DM として扱い、相手の ID（`chatwork:u…`）をルームにする。
  - メンションは、Bot への `[To:…]` と、Bot の発言への返信（`[rp aid=… to=…]`）。全員宛て（`[toall]`）は数えない。本文からは、Bot へのメンションと、その後ろの「名前さん」だけを取り除く。ほかの記法はそのまま渡す。
  - 添付は、本文の `[download:<ファイル ID>]` から取り出す。`download_attachment` は、取得用の URL（30 秒で切れる）を作って取る（25MB まで）。
- 送信：
  - 本文は 65,535 字まで。超えた分は切り、省略したことを書き添える。
  - `reply_to` があれば、返信の記法を付ける。
  - `files` は、種類を問わず 1 つ 5MB まで送る。本文は 1 つ目のファイルに添える。5MB を超えるものがあれば、何も送らずにエラーを返す。
  - DM へは、Bot のコンタクトからダイレクトチャットを探して送る。コンタクトでない人には送れない。
- 承認依頼は、承認者の DM に文字で送る（ボタンはない）。返事は `yes <ID>`・`no <ID>`。
- ペアリング：登録していないグループで Bot にメンションされたとき、または起動後に Bot が新しいグループチャットに追加されたとき、コードを投稿する。投稿に通数の制限はない。
- 回数制限（5 分に 300 回）に達したら、解除の時刻まで取得を止める。その間の送信はエラーにする。ルームごとの投稿の制限（10 秒に 10 回）も、エラーにしてエージェントに伝える。
