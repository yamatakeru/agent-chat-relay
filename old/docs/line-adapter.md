# LINE アダプターの振る舞い（段階 2）

段階 2 の LINE アダプターが従う仕様。2026-11-07 にユーザーと決めた。つなぎ方は ADR 0003（cloud_web）、背景は統括 issue #1 の段階 1 の記録にある。

## どの発言を cc-connect に渡すか

- 登録したグループと、許可した人との 1 対 1 トークでだけ動く。1 対 1 トークは、ルームの登録を要しない。
- 登録していないグループに招待されたら、join の Reply（無料）で一度だけ「未登録のため動作しない」と返し、ログに groupId を残す。あとは無視する。
- グループごとに受信モードを持つ。
  - メンション時（既定）：Bot へのメンション（`mention.mentionees[].isSelf`）がある発言だけを渡す。
  - すべて：すべての発言を渡す（将来使うかもしれない）。
- 渡すのはテキスト、画像、ファイルの発言。音声、動画、スタンプなどは無視する。画像とファイルの扱いは「画像とファイル」の節にある。
- cloud_web の `group_reply_all` は使わない（platform 単位でしか決められないため）。アダプターが渡す発言を選び、`mentioned` を付けて渡す。

## 実行承認

- 承認の言葉は `allow`・`deny`・`許可`・`拒否` の 4 つ。発言全体がその語だけのとき（前後の空白と大文字・小文字は問わない）に限る。`許可` は `allow` に、`拒否` は `deny` に置き換えて渡す。
- 承認の言葉は、メンションがなくても渡す。ただし、承認待ちのときに限る。承認待ちでなければ無視する。
- 承認待ちは、cc-connect から承認依頼の文面が届いたときに始まり、そのルームへの次の送信で終わる。
- 承認できるのは、許可した人なら誰でもよい。将来、承認者のホワイトリストを足せるようにしておく。
- `allow all` は原則禁止。cc-connect が `allow all` とみなす言い方（`allow all`・`approve all`・`yes all`・`allowall` と中国語の 6 語。`core/engine.go` の `approveAllPhrases`・`approveAllSingleTokens`）は渡さず、「このルームでは使えない」と返す。承認待ちの間は、メンションのない発言でも、発言の全体が `allow all` の言い方なら同じく返す。将来、特権ユーザーには許可するかもしれない。
- 承認待ちの間は、承認の言葉以外の発言（メンション付きも含む）を保留し、待ちが終わってから渡す。cc-connect は、承認待ちの間の発言を単語単位で承認の返事として解釈する（`ok`・`no` なども含む）ため、「@Bot ok, but explain first」でも承認されてしまう。
- 受信モードが「すべて」のグループでは、Claude からの質問（AskUserQuestion）への回答待ちの間も、メンションのない発言を保留し、待ちが終わってから渡す。質問への回答待ちの間、cc-connect は次の発言をそのまま回答にする。

## 送信

- Reply トークンは、そのルームで受け取った発言のうち、未使用で 50 秒以内のものがあれば、どの送信にも使う。なければ Push で送る。Reply トークンは受信から 1 分以内に 1 回だけ使え、Reply は通数に数えない。
- cc-connect の補助的な発言（「✅ 許可しました。続行中...」「❌ 拒否しました」「📬 メッセージを受信しました」など）は LINE に出さない。順番待ちが満杯になったときの案内は出す。
- 長い答えは、1 回の送信で最大 5 つの吹き出しに分ける（1 つ 5,000 字まで）。それを超えた分は切り、省略したことを書き添える。
- LINE への送信は、発言の受け付けや cc-connect とのやり取りとは別に行い、LINE の API が遅くても、ほかの処理を止めない。同じルームへの送信は順に 1 つずつ行い、ルームが違えば並行に行う。使う Reply トークンは、送る直前に選ぶ。LINE に送れない状態が続き、ルームの送信待ちが 100 件を超えたら、溢れた分は捨ててログに残す。
- 今月の通数を使い切って Push できないときは、ログに残し、そのルームへ次に Reply で送るときに「今月の上限に達したため返事を送れなかった」と書き添える。Push が要るのは使える Reply トークンがないときなので、その場では伝えられない。

## 画像とファイル

2026-11-07 にユーザーと決めた。画像を LINE へ返すための公開は ADR 0005 にある。

受け取り（LINE から Claude へ）：

- 受け取るのは画像とファイル。画像は 5MB（Claude が受け付ける大きさ）、ファイルは 20MB まで。上限を超えたものは渡さず、「大きすぎるため受け取れない」と Reply で知らせる。外部の URL にある画像（`contentProvider.type` が `line` 以外）は取得しない。
- 画像やファイルにはメンションを付けられない。そこで、同じルームで同じ人が送った画像とファイルを 10 分間預かり、その人が次に Bot あてに送った発言に添えて渡す。Bot あての発言とは、メンションした発言、1 対 1 トーク、受信モードが「すべて」のグループでの発言。承認の言葉には添えない。画像やファイルだけでは反応しない。期限が切れたものは黙って捨てる。
- 取得が終わる前に届いた同じ人の発言は、取得が終わるのを待ってから扱う。
- cc-connect は、受け取った画像とファイルを作業場所の `.cc-connect/attachments/` に保存し、削除しない。アダプターが、保存から 7 日たったものを、起動時と 1 時間ごとに消す。登録を外しても作業場所は残し、消すときは手で消す。
- Claude には、添付が 7 日で消えること、残すものは作業場所の別の場所へ写すことを、システムプロンプト（`examples/line/config.toml` の `append_system_prompt`）で伝える。

返送（Claude から LINE へ）：

- Claude は `cc-connect send --image` で画像を返す。Bash の実行なので、そのたびに承認が要る。承認の設定は変えない。
- アダプターは、画像を公開して画像メッセージで送る（ADR 0005）。JPEG と PNG で 10MB までに限る。それ以外は送らず、理由を知らせる。1MB を超える画像には、縮小したプレビューを作る。
- ファイルは LINE へ返せない（Bot はファイルを送れない）。cc-connect には画像まで受け取れると伝え、ファイルは宣言しない。Claude には、作ったファイルの置き場所を文章で伝えるよう、システムプロンプトで伝える。

## 止まっているとき・切断したとき

- アダプターは動いているが cc-connect とつながっていないときは、Reply で「停止中のため受け付けていない。あとで送り直して」と返し、依頼は捨てる。
- 処理中に cc-connect との接続が切れ、返事が失われた可能性があるときは、すぐ Push でルームに知らせる。
- LINE の Webhook 再送を有効にする。アダプターが止まっている間に届き、あとで再送された依頼は実行しない。Reply で「停止中に届いたため処理していない」と返す。重複は `webhookEventId` で除く。

## ルームの間の分離

- ルームごとに作業場所を丸ごと分ける（添付ファイル、Claude が作るファイル、Claude の会話ログ）。1 対 1 トークも、人ごとに分ける。
- ルームの登録は、cc-connect を再起動せずにできるようにする。仕組みは ADR 0004（multi-workspace モードと、アダプターが書く割り当てファイル）。割り当てのないルームの発言は、cc-connect に渡さない。
